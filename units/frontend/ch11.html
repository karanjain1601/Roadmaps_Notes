Colour, type, motion and effects

1Colour

Seven notations, one of which finally matches how eyes work.

NotationExampleUse it when

Why perceptual uniformity matters in practice

HSL computes lightness arithmetically from RGB, and RGB channels do not contribute equally to perceived brightness — green dominates, blue barely registers. So hsl(60 100% 50%) (yellow) and hsl(240 100% 50%) (blue) claim identical lightness while one is dazzling and the other nearly black. Build a palette by holding HSL lightness constant across hues and the result is visibly uneven, and your contrast ratios vary wildly.

OKLCH fixes this: its L axis tracks perceived lightness, so a constant L across hues genuinely looks like one brightness. The demo measures it.

Deriving colours instead of listing them

Three modern tools CSS
/* Mix two colours in a named space */
--hover: color-mix(in oklch, var(--brand) 85%, black);
--faint: color-mix(in oklch, var(--brand) 12%, transparent);

/* Relative colour syntax: take a colour apart and rebuild it */
--brand-dim:  oklch(from var(--brand) calc(l * 0.8) c h);
--brand-flat: oklch(from var(--brand) l 0 h);          /* desaturated */

/* currentColor: an icon that always matches its text */
.icon { fill: currentColor; }

/* Gamut: give sRGB screens something sensible */
.accent { background: #3B82F6; }
@supports (color: color(display-p3 0 0 0)) {
  .accent { background: color(display-p3 .23 .51 .96); }
}

Dark mode

Declare support
color-scheme: light dark on :root. One line, and form controls, scrollbars and the default canvas all adapt. Without it, your dark page keeps white scrollbars and light-styled selects.
Swap tokens, not rules
Define semantic custom properties once and redefine only those inside @media (prefers-color-scheme: dark). Components never mention a scheme.
light-dark()
--surface: light-dark(#fff, #16202B) puts both values in one declaration, with no media query at all. Requires color-scheme to be set.
A user toggle
Store the choice, set color-scheme and a data-theme attribute on <html> before first paint (a tiny inline script in the head) — otherwise the page flashes the wrong theme.
Dark mode is not an inversion
Pure white text on pure black causes halation for many readers. Use a near-black surface and a slightly dimmed foreground, reduce large saturated areas, and re-check contrast — ratios change, and some pairs that passed in light mode fail in dark.

2Web typography

Loading fonts without shifting the page, and the handful of text properties that do most of the work.

A font declaration with everything that matters CSS
@font-face {
  font-family: "Inter var";
  src: url("/fonts/inter.woff2") format("woff2-variations");
  font-weight: 100 900;        /* one file, the whole range */
  font-display: swap;
  unicode-range: U+0000-00FF, U+2000-206F;  /* subset: latin only */
}

/* Metric overrides on the FALLBACK make the swap geometrically
   neutral, so no layout shift when the web font arrives. */
@font-face {
  font-family: "Inter fallback";
  src: local("Arial");
  ascent-override: 90%;
  descent-override: 22.5%;
  size-adjust: 107%;
}

body { font-family: "Inter var", "Inter fallback", system-ui, sans-serif; }
font-displayBehaviourChoose when
swapFallback immediately, swap whenever the font arrivesDefault choice. Text is never invisible; accept a swap.
optionalVery short block, then never swap this page loadBest Core Web Vitals: zero layout shift, guaranteed. The font appears on the next visit from cache.
fallbackShort block, short swap window, then give upA compromise. Rarely the clearly right answer.
blockInvisible text for up to 3 sIcon fonts only, where a fallback glyph is meaningless.
autoBrowser decides — usually like blockNever deliberately.
The loading chain is two round trips deep
HTML → CSS → font. The preload scanner cannot see a font referenced only inside a stylesheet, so it is discovered late. <link rel="preload" as="font" type="font/woff2" crossorigin> pulls it forward — and the crossorigin attribute is mandatory even for same-origin fonts, or the browser fetches it twice.
WOFF2 only
Universally supported and the best compression. Shipping WOFF, TTF or EOT fallbacks in 2026 is dead weight.
Variable fonts
One file spanning a weight axis usually beats three static weights on total bytes, and gives you every value in between via font-variation-settings or plain font-weight. Check the file size though — a variable font with five axes can be larger than the two weights you actually use.
Subsetting
unicode-range splits a font into ranges the browser fetches only when needed. Building a Latin-only subset of a font that ships Cyrillic and Greek routinely halves it.
System font stacks are free
font-family: system-ui, sans-serif costs zero bytes, zero requests and zero layout shift. For UI text it is often the right answer, and you can spend the budget on a display face for headings only.

3Backgrounds, borders and effects

The decorative layer, with a note on which parts are cheap and which stall the compositor.

Gradients
linear-gradient, radial-gradient, conic-gradient, plus repeating- versions. Interpolate in a perceptual space to avoid the muddy middle: linear-gradient(in oklch, blue, yellow) stays vivid where the sRGB version goes grey. Colour stop positions can be doubled up to create hard bands, which is how you draw stripes without an image.
Multiple backgrounds
Comma-separated, first is on top. Each layer gets its own position, size and repeat. background-clip: text plus a gradient gives gradient text — remember a solid color fallback.
border-radius
Two-value syntax (border-radius: 40px / 20px) gives elliptical corners. Nested radii should not match: an inner radius equals the outer radius minus the padding, or the curves look wrong.
box-shadow versus filter: drop-shadow()
box-shadow follows the border box, so a transparent PNG casts a rectangular shadow. drop-shadow() follows the alpha channel and is what you want for irregular shapes and SVG — at higher cost. Layered soft shadows (three or four, increasing blur and decreasing opacity) look far more natural than one hard one.
backdrop-filter
Frosted glass. Genuinely expensive — it forces the compositor to read back and blur what is behind, every frame. Use sparingly, and honour prefers-reduced-transparency.
mix-blend-mode and background-blend-mode
Photoshop blend modes in CSS. mix-blend-mode creates a stacking context, which is the Chapter 9 trap again.
clip-path and mask
Cut shapes out. clip-path is a hard-edged geometric clip and is animatable between compatible shapes; mask uses an image's alpha and handles soft edges. Both remove the need for a pile of PNG overlays.
Cost, from Chapter 3

opacity and transform are composite-only. background-color, box-shadow and border-radius trigger paint. filter and backdrop-filter trigger paint and can force expensive readbacks. Animating a box-shadow repaints every frame; animating the opacity of a pseudo-element that already carries the shadow does not. That substitution is the standard trick for hover elevation.

4Transitions and easing

Four properties, one curve, and the two additions that finally let entry animations work.

Transition, in full CSS
.panel {
  transition-property: transform, opacity;
  transition-duration: .24s;
  transition-timing-function: cubic-bezier(.2, .8, .3, 1);
  transition-delay: 0s;
  /* shorthand: transition: transform .24s cubic-bezier(.2,.8,.3,1); */
}

/* Never `transition: all` — it animates properties you did not mean,
   including expensive ones added later by a teammate. */

/* Animate INTO existence: @starting-style supplies the "before" state
   for an element that has only just been inserted or made visible. */
@starting-style {
  .panel { opacity: 0; transform: translateY(8px); }
}

/* display and content-visibility are discrete, so they normally jump.
   allow-discrete makes them flip at the right end of the transition. */
.panel { transition-behavior: allow-discrete; }
Easing playground The curve, and a real element moving along it.
the same curve applied to opacity and scale

The four keywords
linear (mechanical, right for a loading bar and almost nothing else), ease (the default, a fast start), ease-in (accelerates — for things leaving), ease-out (decelerates — for things arriving), ease-in-out (for things moving between two on-screen positions).
The rule of thumb
Entrances use ease-out: fast in, gentle settle. Exits use ease-in: gentle start, quick disappearance. Nothing the user is waiting for should be slower than about 300ms; 150–250ms covers most interface motion.
linear()
An arbitrary easing function defined by points, which makes real spring and bounce curves possible in pure CSS: linear(0, 0.6 30%, 1.1 60%, 0.95 80%, 1). Generators produce these from spring physics parameters.
steps()
Discrete jumps. Sprite-sheet animation and typewriter effects.

5Keyframes, the Web Animations API and view transitions

When a two-state transition is not enough.

Keyframes and the eight animation properties CSS
@keyframes rise {
  from { opacity: 0; transform: translateY(12px); }
  to   { opacity: 1; transform: none; }
}

.toast {
  animation: rise .3s ease-out both;
  /* name duration timing delay iteration direction fill play-state */
}

/* fill-mode `both` = apply the from-state before it starts and hold
   the to-state after it ends. Without it the element snaps back. */
Animate the cheap properties
transform and opacity run on the compositor and keep going even when the main thread is busy. Everything else is negotiable at best. Chapter 3's demo measures the difference.
Web Animations API
el.animate(keyframes, options) gives the same engine from JavaScript, with a real Animation object you can pause, reverse, seek and await via .finished. Better than mutating classes when the animation is driven by data — a list reordering, for example.
View Transitions
document.startViewTransition(() => updateDOM()) snapshots the old and new states and cross-fades between them, with named elements morphing from one position to the other via view-transition-name. It makes shared-element transitions — a thumbnail expanding into a detail page — a few lines rather than a library. Works for same-document updates and, with the cross-document form, for ordinary multi-page navigations.
FLIP, when you need it manually
First, Last, Invert, Play: measure the start, apply the change, measure the end, apply an inverting transform, then animate it away. It turns an expensive layout animation into a cheap transform one. View Transitions do this for you in most cases now.

Scroll-driven animation

No scroll listener, no main-thread work CSS
/* Progress bar tied to document scroll */
@keyframes grow { from { scale: 0 1; } to { scale: 1 1; } }
#progress {
  transform-origin: left;
  animation: grow linear;
  animation-timeline: scroll(root block);
}

/* Fade each card in as it enters the viewport */
.card {
  animation: rise linear both;
  animation-timeline: view();
  animation-range: entry 0% cover 30%;
}

/* Wrap in a query so it degrades to no animation, not broken layout */
@supports (animation-timeline: view()) { … }

These run off the main thread, which is the whole point: a scroll-linked effect built with a scroll event listener competes with your JavaScript and stutters, while the CSS version does not.

6Motion and accessibility

Some motion causes physical symptoms. The platform asks the user and tells you.

Vestibular disorders affect an estimated 30% of adults at some point. Large-scale movement — parallax, sliding panes, zooming transitions, autoplaying carousels — can produce genuine nausea and vertigo, not mild irritation. The operating system already asks; you only have to listen.

Two strategies, both correct CSS
/* 1. Blunt global guard — good as a safety net at the end of a
      stylesheet, and better than nothing by a wide margin. */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 2. Better: opt in to movement, keep the fades. Reduced motion does
      not mean no feedback — a cross-fade is usually fine. */
@media (prefers-reduced-motion: no-preference) {
  .panel { transition: transform .3s, opacity .3s; }
}
@media (prefers-reduced-motion: reduce) {
  .panel { transition: opacity .2s; }   /* fade only, no travel */
}
What counts as risky
Large translations across the screen, scaling of big elements, parallax at different depths, rotation, and anything auto-playing and looping.
What is usually fine
Opacity fades, small colour changes, tiny movements under a few pixels, and progress indicators.
Never flash
More than three flashes per second in a large area can trigger seizures. WCAG 2.3.1 is a level-A criterion, which means it is not optional.
Also honour it in JavaScript
matchMedia('(prefers-reduced-motion: reduce)').matches before you start a scripted animation, and listen for changes — people toggle it mid-session.
Give autoplay a pause
Anything moving for more than five seconds needs a visible pause control (WCAG 2.2.2). A carousel without one is a failure regardless of preference settings.

7Check yourself

Five questions.

1. You build a twelve-hue palette by keeping HSL lightness at 55% and only changing the hue. Designers say some colours look "washed out". What is happening?

HSL lightness is computed arithmetically from RGB and does not correspond to perceived brightness. The eye weights green far more heavily than blue — roughly 0.72 against 0.07 in the luminance formula — so hsl(60 …) and hsl(240 …) at the same declared lightness differ enormously in how bright they look, and in their contrast ratio against white. Rebuild the ramp in OKLCH, whose L axis is perceptual: constant L across hues genuinely looks like one brightness, and your contrast ratios become predictable. The demo in section 1 measures the spread both ways.

2. Your headline visibly reflows about a second after load. Name the cause and two fixes.

A web font finished downloading and replaced the fallback, whose metrics differ, so line breaks and box heights changed — a full layout pass, measured as Cumulative Layout Shift. Fixes, in increasing order of effort: preload the font so it arrives before first paint (with crossorigin, or it downloads twice); apply metric overrides — size-adjust, ascent-override, descent-override — to a local fallback face so the swap is geometrically neutral; or use font-display: optional, which simply never swaps on the first visit and guarantees zero shift.

3. Why is transition: all 0.3s considered a mistake?

Three reasons. It animates properties you never intended, including ones a colleague adds later — so a change to height or box-shadow silently becomes an expensive animated one. It can animate layout-triggering properties, costing a full pipeline pass every frame instead of a composite. And it makes the intent unreadable: a reviewer cannot tell what is meant to move. List the properties explicitly; there are almost never more than three.

4. You want a panel to fade in when it is added to the DOM. A plain transition does nothing. Why, and what is the modern fix?

A transition needs a change between two computed values, and a newly inserted element has no previous value to transition from — its first computed style is the final one. The old workaround was inserting it with a class, forcing a reflow by reading offsetWidth, then removing the class. The modern fix is @starting-style, which declares the value the element should start at on first render. If the panel also toggles display, add transition-behavior: allow-discrete so the discrete property flips at the correct end of the transition rather than immediately.

5. A designer wants a hover effect that lifts a card with a larger shadow. How do you implement it so it is cheap?

Do not animate box-shadow — that repaints the element every frame. Put the larger shadow on a pseudo-element that sits behind the card at opacity: 0, and transition its opacity to 1 on hover; combine with a transform: translateY(-2px) for the lift. Both properties are composite-only, so the whole effect runs off the main thread. Wrap it in @media (hover: hover) so touch devices do not get a sticky hover state, and in prefers-reduced-motion: no-preference if the movement is more than a pixel or two.
