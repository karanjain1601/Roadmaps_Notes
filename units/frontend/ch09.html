CHAPTER 09

Layout: flow, flexbox and grid

Four layout modes, each with its own algorithm, plus the positioning system that lifts things out of all of them. This chapter includes the arithmetic — the actual free-space distribution flexbox performs — because "flex: 1 means equal widths" is false often enough to cost you an afternoon.

Part 3 CSS·Reading time 55 minutes·Demos flex calculator, stacking contexts·Prerequisites Chapter 8

1Choosing a layout mode

The decision takes ten seconds once you know the question to ask.

ModeBest whenThe distinguishing question
Normal flowProse, documents, anything stacked verticallyDo I actually need a layout mode at all? A stack of blocks with margins is already correct.
FlexboxOne dimension: a row of buttons, a nav bar, a card's internal stackAm I distributing space along one axis, letting content sizes lead?
GridTwo dimensions, or one dimension where alignment across rows mattersDo I want to define the tracks up front and place things into them?
PositioningOverlays, badges, sticky headers, tooltipsDoes this need to come out of flow and sit on top of something?

The false dichotomy is "flexbox versus grid". They compose: a grid page shell whose cells contain flex rows is the most common structure on the modern web. The genuine distinction is whether the container dictates the sizes (grid) or the items do (flex).

2Normal flow

The default, still doing most of the work, with two behaviours that surprise people every time.

In normal flow, block boxes stack vertically and fill the available inline space; inline boxes flow along a line and wrap. That is nearly all of it. The complications are margin collapsing and formatting contexts.

Margin collapsing

Adjacent vertical margins merge into one, taking the larger value. Horizontal margins never collapse. Three cases:

CaseExampleResult
Adjacent siblingsOne <p> with 24px bottom margin above another with 16px top24px between them, not 40px
Parent and first/last childA <div> with no padding or border containing an <h2> with a top marginThe child's margin escapes and pushes the parent down. The classic "why is there a gap above my container" bug.
Empty blocksAn empty <div> with top and bottom marginsThey collapse through each other into one
What stops collapsing
Padding or a border on the parent; overflow other than visible; display: flow-root; being a flex or grid item; floats; absolute positioning.
The clean modern answer
Stop fighting it. Use gap in flex and grid containers, which never collapses, or apply spacing in one direction only — the "owl" pattern .stack > * + * { margin-block-start: 1rem } puts space between children and never above the first.

Block formatting contexts

A BFC is an isolated layout region. Inside one, margins do not collapse with anything outside, floats are contained, and boxes do not overlap floats from outside. You create one with display: flow-root — the purpose-built keyword — or, historically, with overflow: hidden, which worked by accident and clipped your content as a side effect.

Floats, briefly

Floats exist to wrap text around an image. That is now their only good use; every layout they were once conscripted for is better done with flex or grid. The one thing worth remembering is that a floated child does not contribute to its parent's height unless the parent establishes a BFC — the "clearfix" problem, solved today by one line of display: flow-root.

3Flexbox

One axis, content-driven sizing, and an arithmetic that is genuinely worth learning rather than guessing at.

Main axis
Set by flex-direction. row (default) or column, each with a -reverse. Justification happens along it.
Cross axis
Perpendicular. Alignment happens along it.
Container properties
flex-direction, flex-wrap, justify-content, align-items, align-content (multi-line only), gap.
Item properties
flex-grow, flex-shrink, flex-basis, align-self, order.

The sizing algorithm

This is the part people skip. It runs in four steps:

  1. Base size. Each item's flex-basis, or its content size when the basis is auto and no width is set.
  2. Free space. Container inner size, minus the sum of base sizes, minus the gaps.
  3. Positive free space is distributed in proportion to each item's flex-grow.
  4. Negative free space is removed in proportion to flex-shrink weighted by base size — a bigger item gives up more. That weighting is the step everyone forgets.
Shorthands worth memorising CSS
flex: 1;          /* 1 1 0%   — equal widths regardless of content   */
flex: auto;       /* 1 1 auto — grow and shrink from content size    */
flex: initial;    /* 0 1 auto — the default: shrink but never grow   */
flex: none;       /* 0 0 auto — fixed at content size, never flexes  */
flex: 0 0 240px;   /* a rigid sidebar                                 */

/* The distinction that trips everyone up:
   flex: 1    -> basis 0, so content length is IGNORED. Equal columns.
   flex: auto -> basis auto, so content length still counts. Unequal. */

The gotchas, all of them

min-width: auto
A flex item's minimum size defaults to its content's minimum, so it refuses to shrink below its longest unbreakable word. This is why a long URL or a <pre> blows out a layout. Fix with min-width: 0 on the item, or overflow: hidden, which has the same effect.
Percentage flex-basis with an auto-height container
In a column flex container whose height is not definite, percentage bases have nothing to resolve against and behave as auto.
order changes paint order, not DOM order
Tab order still follows the DOM. Reordering visually without reordering the markup produces a focus sequence that jumps around the screen — a WCAG 2.4.3 failure. Use it for a genuinely equivalent reflow, not to reposition unrelated content.
align-items: stretch is the default
Which is why sibling cards match heights automatically, and why an image inside a flex row sometimes stretches oddly. align-items: start or align-self: start fixes it.
margin: auto in a flex container
Absorbs free space on that side. margin-inline-start: auto on one item pushes it and everything after it to the end — cleaner than justify-content: space-between when only one item needs separating.
gap is not margin
It applies only between items, never at the edges, and never collapses. Prefer it to child margins in every flex and grid container.

4Grid

Define the tracks, then place things into them. Two dimensions at once, and the only mode where you can overlap without positioning.

The vocabulary in one block CSS
.page {
  display: grid;

  /* fr = a share of the space LEFT OVER after fixed tracks and gaps */
  grid-template-columns: 240px 1fr 320px;
  grid-template-rows: auto 1fr auto;
  gap: 1rem 1.5rem;              /* row-gap column-gap */

  /* Named areas: readable, and the layout is visible in the source */
  grid-template-areas:
    "head head head"
    "nav  main aside"
    "foot foot foot";
}
.masthead { grid-area: head; }
.content  { grid-area: main; }

/* The one-line responsive grid. No media query needed. */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(18rem, 100%), 1fr));
  gap: 1rem;
}
FunctionDoes
repeat(3, 1fr)Three equal tracks.
minmax(200px, 1fr)At least 200px, otherwise a share of free space. The workhorse.
auto-fillCreate as many tracks as fit, keeping empty ones. Items stay their minimum width.
auto-fitSame, but collapse empty tracks so the existing items expand to fill the row. Usually what you want.
min-content / max-contentThe narrowest the content can be without overflowing / its natural unwrapped width.
fit-content(30ch)Like max-content but capped.
span 2, 1 / -1Placement: span two tracks; from the first line to the last.
grid-auto-flow: denseBackfill gaps with later items. Visually tidy, but it decouples visual order from DOM order — same accessibility caveat as flex order.
subgridA child grid adopts the parent's track sizes, so nested content aligns across siblings. The fix for "my card headings do not line up".
Implicit tracks
Items placed outside your declared grid create new tracks automatically, sized by grid-auto-rows / grid-auto-columns. Useful for lists of unknown length; confusing when it happens by accident.
Alignment, six properties
justify-* works along the inline axis, align-* along the block axis. -items aligns contents within their cells, -content aligns the whole grid within the container, -self overrides for one item. place-items: center is the shorthand for perfect centring in two lines of CSS.
Overlap without positioning
Two items placed in the same cell stack, and z-index orders them. This is the tidiest way to build a hero with text over an image — no absolute positioning, and the grid still sizes to its content.
Masonry
Item-packed layouts of unequal height are still being standardised (grid-template-rows: masonry and the competing item-flow proposal). Until it lands, columns plus JavaScript, or a flex column split, remain the options.
The four layouts that cover most pages

Centred column: width: min(65ch, 100% - 2rem); margin-inline: auto. Sidebar + content: grid-template-columns: minmax(0, 240px) minmax(0, 1fr). Responsive cards: the auto-fit minmax line above. Sticky footer: min-height: 100svh; grid-template-rows: auto 1fr auto. Note minmax(0, …) in the sidebar case — without it, grid tracks also default to a min-content floor and refuse to shrink, exactly like flex items.

5Positioning, containing blocks and stacking

Five values, one question ("positioned relative to what?"), and the z-index rules that make it all make sense.

ValuePositioned againstNotes
staticNothing — normal flowThe default. top/left and z-index are ignored.
relativeIts own normal positionStill occupies its original space; the gap stays. Also becomes a containing block for absolute descendants — its most common real use.
absoluteThe nearest positioned ancestorRemoved from flow entirely, so the parent no longer accounts for it.
fixedThe viewportUnless an ancestor has transform, filter, perspective, backdrop-filter, contain: paint or will-change on one of those — then that ancestor becomes the containing block and your fixed header scrolls away.
stickyIts scroll container, within its parentRequires at least one inset (top: 0) and a parent taller than it. Fails silently if any ancestor has overflow other than visible.

Stacking contexts

Elements paint in a defined order. Within one stacking context, the order is: the root background, then negative z-index, then in-flow blocks, then floats, then inline content, then z-index: 0 and auto positioned elements, then positive z-index.

The critical rule: z-index only competes within the same stacking context. A child with z-index: 9999 inside a context whose own index is 1 can never paint above a sibling of that context with index 2. This is the entire explanation for "my modal is behind the header and no z-index fixes it".

Stacking context explorer Real overlapping boxes. Watch what creates a context and what it traps.

    What creates a stacking context
    The root element; position other than static with a z-index other than auto; any position: fixed or sticky; opacity below 1; transform, filter, backdrop-filter, perspective, clip-path, mask, mix-blend-mode other than normal; isolation: isolate; will-change naming any of these; contain: paint or content-visibility; and being a flex or grid item with a z-index.
    isolation: isolate
    Creates a stacking context and nothing else — no visual side effect at all. The right tool when you deliberately want to contain a component's z-indexes so they cannot leak.
    The top layer
    <dialog>.showModal() and the Popover API render in a browser-level layer that sits above every stacking context in the document. It is the only genuine escape, and it is why the native dialog ends the modal-z-index problem permanently.
    Anchor positioning
    anchor-name and position-area let an absolutely positioned element attach to another element anywhere in the document, with automatic flipping when it would overflow. It replaces the positioning half of most tooltip and dropdown libraries.
    A z-index scale
    Define five or six named values as custom properties — --z-dropdown: 100, --z-sticky: 200, --z-modal: 400 — and never write a raw number. The value of the scale is not the numbers; it is that a code review can see the intent.

    6Intrinsic sizing

    The keywords that let content decide, and the two floors that make things refuse to shrink.

    KeywordMeans
    min-contentThe narrowest the box can be without its content overflowing — for text, the longest unbreakable word.
    max-contentThe width the content wants with no wrapping at all. A long paragraph becomes one very long line.
    fit-contentShrink-wrap the content but never exceed the available space. width: fit-content; margin-inline: auto centres a box sized to its own content.
    stretchFill the containing block including margins — what width: 100% does not quite do when margins are present.
    The automatic minimum size, in both modes

    Flex items get min-width: auto; grid items get an automatic min-content floor on their track. Both mean the same thing in practice: a child containing a long URL, a wide table or a <pre> block will refuse to shrink and will blow out your layout, with no obvious culprit in devtools. The fixes are min-width: 0 on the flex item, minmax(0, 1fr) instead of 1fr for the grid track, or overflow: hidden on the child. If you learn one debugging reflex from this chapter, make it this one.

    7Check yourself

    Six questions, three of them things you will debug this month.

    1. Three flex items with flex: 1 contain "OK", "Cancel" and "Save and continue to payment". Are they the same width? What if you change to flex: auto?

    With flex: 1 they are the same width, because the shorthand expands to 1 1 0% — a base size of zero, so every item starts from nothing and all the space is free space, distributed equally. With flex: auto (1 1 auto) each item starts at its content width and only the remaining space is shared equally, so the long label stays wider. This single distinction accounts for most confusion about flexbox, and the demo in section 3 shows the arithmetic.

    2. A flex row containing a long URL overflows its container and produces a horizontal scrollbar. Why, and what is the one-line fix?

    Because a flex item's min-width defaults to auto, which resolves to its content's minimum size — and an unbreakable URL has a large minimum. The item therefore refuses to shrink below that, no matter what flex-shrink says. Add min-width: 0 to the item (or overflow: hidden, which has the same effect). In a grid the equivalent is writing minmax(0, 1fr) instead of 1fr. Add overflow-wrap: anywhere if you also want the URL itself to break.

    3. Your modal has z-index: 9999 and still renders behind the site header. Give two plausible causes.

    First and most likely: the modal is inside an ancestor that creates a stacking context with a lower effective index than the header's — a container with transform, opacity: .99, filter, or its own z-index. z-index only competes among siblings within one context, so 9999 inside a context of 1 loses to a context of 2. Second: the header creates a context that simply comes later, and the modal is not a sibling of it at all. The durable fix is not a bigger number — it is to render the modal in the top layer with <dialog>.showModal(), or to portal it to <body> and use a named z-index scale.

    4. position: sticky; top: 0 does nothing. What are the three usual reasons?

    One: an ancestor has overflow set to anything other than visible — including hidden, auto and clip — which makes it the scroll container, and the element sticks within that instead of within the page. Two: the sticky element's parent is not taller than the element, so there is no range in which to stick. Three: no inset was set at all; position: sticky without top, bottom, left or right is inert. A fourth, less common: the parent is a flex container with the default align-items: stretch, so the element is full height and again has nowhere to travel.

    5. What is the difference between auto-fill and auto-fit, and which do you usually want?

    Both create as many tracks as will fit. auto-fill keeps the empty ones, so with two cards in a container wide enough for five you get two cards at their minimum width and three empty tracks of space to the right. auto-fit collapses the empty tracks to zero, so the two cards expand to fill the row. auto-fit is usually what a card grid wants; auto-fill is right when the grid must keep a consistent column rhythm regardless of how many items exist — a calendar, for instance.

    6. There is a mysterious gap above your container even though the container has margin-top: 0. What is happening?

    Margin collapsing between a parent and its first child. If the container has no top padding, no top border and is not a formatting-context root, the first child's top margin does not stay inside — it collapses out and pushes the parent down instead. Any of these stops it: adding padding-block-start or a border to the parent, setting display: flow-root, or making the parent a flex or grid container. The structural fix is to stop putting top margins on children at all and use gap or the * + * pattern.
