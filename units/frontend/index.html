Front-end Developer

The whole roadmap written out as one course: what the browser does with your files, HTML that means something, CSS that survives a redesign, JavaScript in an environment you do not control, the framework layer and the build layer underneath it, and everything between "it works on my machine" and "it is fast and safe for a stranger on a slow phone". Thirty chapters, each one a page you can read end to end.

·How to use this unit

Read it in order if the front end is new to you. Jump if it is not. Either way, the demos are the point.

Every chapter is one HTML page in this folder. Nothing loads from a server, nothing loads from a parent directory, and the demos run real code rather than playing an animation of it — when a chapter says a layout thrashes or a bundle splits or a specificity war is lost, there is a control on the page that lets you cause it and watch the number move.

The unit deliberately overlaps with the separate HTML, CSS, React, Vue, Angular, Next.js and Design Systems units on the same line. This one is the spine: it explains the platform and the decisions. Those go deeper into one technology each. If you only read one, read this one.

New to the front end

Straight through. Parts 1 to 4 are the foundation and take the longest; do not skip Part 1 because it looks like theory. It is the reason the rest makes sense.

A note on versions

Front-end tooling churns faster than the platform does. Chapters about the platform — HTTP, the DOM, CSS, the event loop, accessibility — are written to last. Chapters about tooling name specific tools because a vague chapter would be useless, but they are organised around the problem each tool solves, so the reasoning survives the tool being replaced.

·The thirty chapters

Grey cards are planned; blue cards are written and clickable.

Self-contained by design

Everything this unit needs lives in this folder: index.html, chNN.html and assets/. Copy the folder to a USB stick, a phone, a plane — it still works. The only outbound link is the one back to the catalogue in the breadcrumb, and it is optional.

How a chapter is built

Intuition first, then the precise rule, then code you can run, then a demo wired to the real behaviour. Comparison tables where a decision has to be made, and a few self-check questions at the end that hide their answers until you ask.
