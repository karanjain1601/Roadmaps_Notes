Docker

A container is an ordinary Linux process with a restricted view of the machine. There is no small virtual machine inside it, no second kernel, and nothing magical — just three kernel features and a tarball. This unit shows you those parts first, because almost every confusing thing Docker does is obvious once you know which of them is responsible.

Conventions used throughout

Callouts

Key is a fact worth remembering. Trap is something that will bite you. Warn is destructive. Tip is a shortcut worth adopting.

Commands

Anything after $ is safe to run on a scratch machine. Commands that delete data or change host state say so first.

Honesty about models

Where a demo models something rather than computing it exactly, the assumptions are listed under it and the numbers are labelled as estimates.

Where the demos come from

Real implementations

The SHA-256 in chapter 3 is a genuine implementation, verified against a reference. Layer and image digests it produces are computed the way Docker computes them.

Real rule engines

The cache invalidation, capability and cgroup demos evaluate actual rules, so their answers change when the inputs do rather than following a script.

Everything offline

No network calls, no build steps, no analytics. Each chapter is one HTML file plus two shared assets, and works from a local folder.
