Interior routing protocols

Inside one organisation, routers need to agree on the topology and recompute quickly when it changes. This chapter is how they do that, and — more usefully — where the seconds go when a link fails, because the answer surprises almost everyone.

7.1Two ways to solve the problem

Distance vector against link state
Distance vectorLink state
Each router knowsOnly what its neighbours told it: "I can reach X at cost 5"The whole topology, and computes paths itself
AnalogyAsking for directions at every junctionHaving the map
SharesIts routing table, periodicallyIts own links, when they change
LoopsStructurally possible — a router can believe a path that runs through itself. Needs split horizon, poison reverse, hold-downsStructurally prevented: everyone computes from the same map
ConvergenceSlow. Information propagates hop by hop, and hold-down timers deliberately delay it furtherFast. One flood, then everyone recomputes independently

ExamplesRIP, and EIGRP as an advanced hybridOSPF, IS-IS
Link state won, and the reason is loops rather than speed

Distance vector's problem is not that it is slow — it is that a router believes what it is told without being able to verify it, so two routers can each think the path to a network runs through the other. The mitigations for that (split horizon, poison reverse, hold-down timers, the count-to-infinity limit of 15 hops in RIP) all work by deliberately slowing convergence down, which is why the two weaknesses are really one. A link-state protocol distributes the raw topology instead of conclusions about it, so every router computes shortest paths from an identical map with Dijkstra's algorithm, and a loop cannot form because nobody is trusting anybody's arithmetic but their own. That is why OSPF and IS-IS are what you will actually meet, and why RIP survives only in places nobody has revisited.

7.2OSPF

How it works, in the order it happens 
1  DISCOVER NEIGHBOURS
   Hello packets to 224.0.0.5, every 10 seconds by default.
   Both ends must agree on area, subnet, timers, MTU and
   authentication — a mismatch in ANY of those means the
   adjacency never forms, and the log message usually names
   the offending one. Check MTU first; it is the least
   obvious.

2  ELECT (on broadcast segments only)
   A designated router and backup, so that n routers on one
   LAN form 2n adjacencies rather than n(n−1)/2. Point-to-
   point links skip this entirely, which is one reason to
   configure LAN links as point-to-point where you can.

3  EXCHANGE the link-state database until both ends match.

4  FLOOD link-state advertisements when anything changes.
   Each LSA is reflooded unchanged, so every router in the
   area ends up with an identical database.

5  RUN DIJKSTRA over that database to produce a shortest
   path tree, and install the results.

COST
  By default, reference bandwidth ÷ interface bandwidth,
  with a reference of 100 Mbps. So:
     10 Mbps → 10      100 Mbps → 1
      1 Gbps → 1       10 Gbps  → 1        ← the problem
  Every link at or above 100 Mbps has cost 1, so a gigabit
  path and a ten-gigabit path look identical. RAISE THE
  REFERENCE BANDWIDTH on every router in the domain, to
  something above your fastest link, and do it consistently
  or the costs disagree.

AREAS
  Area 0 is the backbone; every other area must touch it.
  An area boundary is a FLOODING boundary — LSAs do not
  cross it, so a topology change inside area 2 does not
  cause an SPF run in area 3. That containment is the whole
  point, and it only works if addressing lets you summarise
  at the boundary.                                    → ch 4

7.3Where convergence time goes

Anatomy of a reconvergence

A link fails. Five things must happen. One of them dominates completely at default settings.

The link that stays up while forwarding nothing

Every detection mechanism above assumes a failure is visible. The dangerous case is the one that is not: a fibre pair where one direction has failed, a provider circuit that stays electrically up across an intermediate device while dropping traffic in the middle, or a line card that accepts frames and discards them. The physical layer reports the link as up, hellos may still arrive in one direction, and the routing protocol sees no reason to reconverge — so traffic is black-holed indefinitely while every dashboard shows green. This is what BFD is genuinely for: it is not primarily a speed optimisation but an independent bidirectional liveness check that fails when traffic stops flowing, regardless of what the link light says. Two supporting habits: enable link-state debounce so a flapping port does not thrash the protocol, and monitor end-to-end reachability separately from interface state, because interface state is exactly the thing lying to you in this scenario.

7.5Design rules that hold everywhere

Independent of which protocol you chose 
SUMMARISE AT BOUNDARIES
  This is why chapter 4 mattered. A boundary that cannot
  summarise gives you all the operational cost of areas with
  none of the benefit.

KEEP AREA 0 SMALL AND STABLE
  It carries everything between areas. Instability there is
  instability everywhere.

PASSIVE BY DEFAULT
  Enable the protocol on interfaces facing other routers,
  and make every user-facing interface passive: advertise
  the subnet, form no adjacency. A router should never form
  an adjacency with something on an access VLAN.

AUTHENTICATE ADJACENCIES
  Otherwise anything on the segment can inject routes. This
  is a real attack and the control is one line per link.

FILTER WHAT YOU REDISTRIBUTE
  Redistribution between protocols is where routing loops
  and route feedback are born. Always filter, always tag,
  and never redistribute in both directions without a
  loop-prevention tag.

TUNE TIMERS DELIBERATELY, NOT ENTHUSIASTICALLY
  Aggressive hellos on an unstable link cause adjacency
  flapping, which triggers reconvergence, which is worse
  than slow detection. Prefer BFD, which is designed for
  the job, over shortening hellos.

DO NOT RUN A ROUTING PROTOCOL TO A DEVICE YOU DO NOT TRUST
  A static route or BGP with filtering is the right answer
  at any boundary you do not control.                 → ch 8
Your OSPF network takes 45 seconds to reconverge. What do you change first?

Failure detection, because at default settings it is roughly 80% of the total and everything else is rounding error. With a 10-second hello and a 40-second dead interval, the protocol spends forty seconds deciding that a neighbour is gone before any of the interesting work starts — and during all of it, traffic is being forwarded into a hole. Compare that with the other terms: flooding across a handful of hops is tens of milliseconds, the Dijkstra computation for a few hundred routers is under twenty milliseconds, and installing a few thousand prefixes is well under a second. People frequently reach for the SPF timers first because computation feels like the expensive part, and it is not remotely the bottleneck. The right fix is BFD rather than shorter hellos. Shortening hellos to sub-second works but loads the control plane and, more importantly, makes the protocol fragile on a link with any jitter — a brief delay drops the adjacency, which triggers a reconvergence that is worse than the slow detection you were trying to avoid. BFD is a lightweight dedicated liveness protocol, frequently offloaded to hardware, that detects in the low hundreds of milliseconds and, crucially, verifies traffic actually flows in both directions, so it also catches the unidirectional failure that hellos and link lights miss entirely. After BFD, throttle the LSA generation and SPF scheduling delays — those default to seconds for historical reasons and modern implementations handle millisecond values comfortably, with exponential backoff so a flapping link does not cause continuous recomputation. Together those changes take a 45-second reconvergence to well under a second.

Why are OSPF areas worth the complexity?

Because an area boundary is a flooding boundary, and flooding is what limits how large a single link-state domain can grow. Inside one area, every router holds an identical copy of the topology database and every topology change is flooded to all of them, each of which then reruns the shortest-path calculation. That is fine at fifty routers and increasingly unpleasant at a thousand: the database grows, every flap anywhere causes work everywhere, and a single unstable link in one corner keeps the entire network recomputing. Splitting into areas contains that — a change inside area 2 is flooded within area 2, summarised at its border, and area 3 never learns about it or recalculates. The blast radius of instability becomes the area rather than the network. There are two honest qualifications. First, the benefit depends almost entirely on being able to summarise at the boundary, which depends on the address plan from Chapter 4; an area boundary that has to advertise forty specifics because the addressing is not contiguous gives you all the operational complexity of areas with none of the containment. Second, modern hardware has moved the threshold considerably — a few hundred routers in a single area is unremarkable today, so areas are less often forced by scale than they were, and a single-area design is genuinely simpler to operate. The other reason areas persist is policy rather than scale: stub and not-so-stubby areas let you keep external routes out of parts of the network entirely, which reduces table size on small edge routers, and area boundaries are a natural place to apply filtering.

Should you use EIGRP, OSPF or IS-IS?

For most enterprises, OSPF, and the reason is interoperability rather than technical superiority. It is a genuine standard implemented by every vendor, so the network can survive a procurement decision; the operational knowledge is widespread, which matters for hiring and for handover; the documentation and troubleshooting material is extensive; and its behaviour is well understood in every failure mode you will meet. Those are unglamorous advantages and they dominate the decision in practice. EIGRP is genuinely good — its feasible-successor mechanism gives it a precomputed loop-free backup path, so failover is often faster than OSPF's recompute, and it is simpler to configure at small scale. Its problem is that despite being published as an informational standard it remains effectively single-vendor in practice, so choosing it constrains every future hardware decision. That is a real cost that is easy to discount at the moment of choosing and expensive later. IS-IS is technically excellent, arguably the best of the three at scale — it runs directly over layer 2 rather than over IP, which makes it harder to attack remotely, it extends cleanly to new address families so IPv6 needed no separate protocol instance, and it scales to very large topologies. It dominates in service provider networks. Its drawback in an enterprise is the smaller pool of engineers who have operated it, which makes support harder. And note the modern alternative that is displacing all three in data centres: BGP as an interior protocol in a leaf-and-spine fabric, which trades the automatic topology discovery of an IGP for explicit, filterable policy and predictable behaviour at very large scale.

Recap

  1. Link state distributes the map; distance vector distributes conclusions. That is why loops differ.
  2. Distance vector's loop mitigations all work by slowing convergence, so its two weaknesses are one.
  3. An OSPF adjacency needs area, subnet, timers, MTU and auth to match. Check MTU first.
  4. Default OSPF cost makes every link above 100 Mbps identical. Raise the reference bandwidth everywhere.
  5. Detection is around 80% of default convergence time. Everything else is rounding error.
  6. Use BFD rather than aggressive hellos — it is designed for the job and catches unidirectional failures.
  7. A link that is up while dropping traffic is the failure no timer catches and BFD does.
  8. An area boundary is a flooding boundary, and it only pays if you can summarise there.
  9. Passive by default, and authenticate every adjacency.
  10. Filter and tag everything you redistribute, or you are building a loop.
