The whole model, in five sentences

If you retain nothing else, retain these.

Git, entire

  • Git is a key–value store where the key is the hash of the value, holding four object types: blob, tree, commit, tag. (ch. 2)
  • A commit names one complete tree plus its parents — it stores no diff, and every diff you see was computed on demand. (ch. 2, 7)
  • Work moves between three trees: HEAD, the index, and the working tree. Nearly every command moves content between two of them. (ch. 3, 8)
  • Refs are mutable names into an immutable graph, and the reflog remembers every value each one has held. (ch. 4)
  • Because a parent's hash is inside a commit's hash, changing any commit changes every descendant — which is all that merge, rebase, revert and force-push are really about. (ch. 10–13)

Everything else in this unit is a consequence. Branches are cheap because a ref is a 41-byte file. A merge needs three inputs because two versions cannot be reconciled without knowing where they diverged. Rewriting published history fails because other people's clones still reach the old commits. Cherry-picking succeeds where patching fails because it is a merge, not a text operation.

Revision and range syntax

The vocabulary from chapters 4 and 6, in one place.

Naming one commit
HEAD, @Where you are
HEAD~3Three generations back, always first parents
HEAD^2The second parent — merges only
HEAD^{tree}That commit's tree object
v1.0^{}Peel an annotated tag to its commit
@{u}, @{push}Upstream; where a push would go
HEAD@{2}, main@{yesterday}From the reflog
:/fix quotingYoungest commit whose message matches
HEAD:src/app.js, :2:src/app.jsA blob in a commit; a conflict stage in the index
Naming a set of commits
BEverything reachable from B
A..B = ^A BWhat B has that A does not
A...B in logSymmetric difference — unique to either side
A...B in diffMerge base of A and B, compared with B
A^!Just A, excluding its parents
--allEvery ref as a starting point
The two that cause the most confusion

~ walks generations; ^n picks a parent. They are identical until they meet a merge. And A...B means two unrelated things depending on whether you typed log or diff — symmetric difference in one, merge-base-to-B in the other.

The configuration, in one block

Everything this unit recommended, collected. Run it once on a new machine.

~/.gitconfig — the whole thing
$ git config --global user.name "Your Name"
$ git config --global user.email "you@example.com"

# sane defaults                                                      (ch. 1)
$ git config --global init.defaultBranch main
$ git config --global pull.ff only
$ git config --global push.default simple
$ git config --global push.autoSetupRemote true
$ git config --global push.useForceIfIncludes true
$ git config --global fetch.prune true
$ git config --global log.date iso
$ git config --global column.ui auto
$ git config --global help.autocorrect prompt

# readable diffs and survivable merges                          (ch. 7, 11)
$ git config --global diff.algorithm histogram
$ git config --global diff.colorMoved zebra
$ git config --global merge.conflictStyle zdiff3
$ git config --global rerere.enabled true
$ git config --global rerere.autoUpdate true

# committing                                                     (ch. 5, 12)
$ git config --global commit.verbose true
$ git config --global rebase.autosquash true
$ git config --global rebase.autostash true
$ git config --global rebase.updateRefs true

# signing with an SSH key you already have                            (ch. 5)
$ git config --global gpg.format ssh
$ git config --global user.signingkey ~/.ssh/id_ed25519.pub
$ git config --global commit.gpgsign true
$ git config --global tag.gpgsign true

# line endings — input on macOS/Linux, true on Windows                (ch. 1)
$ git config --global core.autocrlf input

# submodules, if you use them                                       (ch. 17)
$ git config --global submodule.recurse true
$ git config --global push.recurseSubmodules check
$ git config --global diff.submodule log

# performance on large repositories                              (ch. 15, 17)
$ git config --global core.fsmonitor true
$ git config --global feature.manyFiles true

# aliases                                                             (ch. 1)
$ git config --global alias.st "status --short --branch"
$ git config --global alias.lg "log --oneline --graph --decorate -20"
$ git config --global alias.last "log -1 --stat"
$ git config --global alias.unstage "restore --staged"
$ git config --global alias.amend "commit --amend --no-edit"

$ git config --global --list --show-origin | less     # check the result

Per-repository, two more are worth committing rather than configuring: a .gitattributes settling line endings and generated files (chapters 11, 17, 23), and a .git-blame-ignore-revs listing formatting commits (chapter 6). Both travel with the repository, which is the point.

Glossary

Defined the way Git means them, not the way conversations use them.

blob
The stored content of one file. Has no name, no path and no timestamp.
tree
A directory: a sorted list of mode, type, hash and name entries.
commit
One tree hash, zero or more parent hashes, author, committer, message. No diff.
gitlink
A tree entry with mode 160000 naming a commit in another repository — a submodule.
ref
A name pointing at an object, stored as a file under .git/refs or packed into packed-refs.
HEAD
Usually a symbolic ref naming the current branch; when it holds a hash directly, you are detached.
index
Also staging area, also cache. The file listing exactly what the next commit will contain.
merge base
The best common ancestor of two commits — the third input to every merge.
fast-forward
Moving a branch ref forward when its tip is already the merge base. No merge commit is created.
reachable
Walkable from some ref, index entry, stash or reflog entry. Unreachable objects are pruned eventually.
reflog
The local, per-ref log of every value that ref has held. Not cloned, not pushed, expires.
refspec
[+]<src>:<dst> — the rule mapping refs between two repositories.
patch id
A hash of a diff with whitespace and position removed, so the same change has the same id under a different commit hash.
porcelain / plumbing
Human-facing commands whose output may change, versus low-level commands whose output is stable.
packfile
Many objects in one file, some stored as deltas against others. Where Git's compression actually happens.
promisor remote
The remote a partial clone fetches missing objects from, on demand.

And the exercise worth doing

Twenty minutes, and it converts the model from something you have read into something you have operated. Everything else in this unit is a consequence of what those five commands do.
