Git & GitHub

Git is a small, strange, beautiful idea — a content-addressed object store with a few pointers on top — wrapped in a command-line interface that hides it from you. This unit shows you the machine first, then every command becomes obvious rather than memorised. Then it does the same for GitHub, from pull requests to Actions to the API.

Before you start

What this assumes

A terminal you're not scared of, and that you've typed git commit at least once — even if you copied the incantation from somewhere.

No prior Git theory needed.

How to read it

Every chapter has runnable demos wired to the real algorithms, not animations of them. The hashes you see are hashes Git would produce.

Conventions used throughout

Shell blocks show the prompt as $. Output lines have no prompt. Where a command's output matters it is shown verbatim, wrapped where necessary.

reading a shell block
$ git status --short
 M src/parser.js        # a line without $ is output, not something you type
?? notes.txt

Commands are written for Git 2.40 or newer. Where a modern command replaces an older one — git switch and git restore in place of overloaded git checkout — both appear, because you will read the old one in every answer you find online.

Portability

This folder is self-contained. It needs no server, no build step and no sibling files: copy units/gitgithub/ anywhere and open index.html. The only outbound link is the one back to the catalogue at the top, and the only network request is for the two web fonts — the pages fall back to system fonts offline.

Where the demos come from

The hashing demo implements SHA-1 in the page and builds Git's exact object headers, so its output matches git hash-object byte for byte. Nothing is faked or pre-recorded.
