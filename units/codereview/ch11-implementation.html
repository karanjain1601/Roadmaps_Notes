Complexity is a good metric being used for the wrong thing

Cyclomatic complexity is the number of linearly independent paths — a genuine lower bound on the test cases needed to cover every branch. That is real and worth knowing.

It is not a proxy for how hard code is to read, and it is routinely used as one. A function of complexity 12 written as guard clauses reads better than one of complexity 6 nested four deep, and any gate on the number will pass the second and block the first.

Nesting depth caught the difference where complexity did not — 4 against 1. That is worth knowing when someone quotes a complexity number at a review: ask what it is being used to decide.

What nesting costs a reader

To understand the innermost line of a nested function, a reader must hold every enclosing condition in mind simultaneously. Depth is the number of held conditions.

Why guards work, mechanically

Each guard discharges its condition and leaves. By the last line of the guarded version the reader holds nothing — every earlier case has already returned, so the final line is unconditional.

The nested version demands four held conditions at the same point. Same logic, same complexity number, four times the working memory.

This is also why "extract a method" often helps and sometimes does not. Extracting an inner block reduces depth in the caller and creates a new function whose own preconditions are now implicit — you have moved the held context rather than discharged it. Guards discharge; extraction relocates.

When duplication is the right answer

Duplication costs you every change applied N times. Abstraction costs you the build, plus — if the copies later turn out to differ — unpicking it, plus a parameter for every way they differ. Those two curves cross, and where they cross is not where "DRY" suggests.

Which turns it into a better review question

Not "is this duplicated" but "will these two things change together?"

Duplication of things that change together is debt. Duplication of things that merely look alike is the correct answer — and merging them creates a shared abstraction that both callers now have to fight, which is considerably harder to undo than a copy-paste.

Hidden state

Six sources, one shared property
SourceSymptom
Mutates an argumentCaller's data changes without an assignment
Module-level mutable valueTwo callers interfere; tests pass in isolation
Cached without invalidationCorrect once, stale forever
Reads the clock or randomNot reproducible; tests flaky by construction
Reads an environment variableBehaviour differs by machine
Order-dependent initialisationWorks until someone reorders imports

All six break the same property: the function's behaviour is not a function of its arguments. That single property is what makes code hard to reason about, hard to test, and unsafe to change.

Hidden state multiplies the test space

A function with 4 input classes and no hidden state needs 4 test cases. Add one hidden boolean and it needs 8. Three hidden flags and it needs 32.

Nobody writes those 32. So a function with hidden state is not merely harder to test — it is a function whose tests are known to be incomplete, and the incompleteness grows exponentially rather than linearly.

The one to look for hardest in a diff is argument mutation, because it is invisible at the call site. normalise(config) that modifies config reads exactly like one that does not.

Clever and clear

The usual framing — "prefer clear over clever" — is agreed with by everyone and settles nothing, because nobody thinks their own code is the clever kind. A more useful version is a question about who pays.

Three tests that discriminate
AskIf no
Can you predict it without running it?Every future reader runs it too
Does the shortcut have a name?Named techniques are learnable; unnamed ones are not

The second is the most discriminating and the least used. A bit-twiddling trick with a name — "Brian Kernighan's algorithm", "the two-pointer technique" — is a thing a reader can look up once and know forever. The same trick without a name is a puzzle re-solved by every reader.

So the review comment is often not "this is too clever" but "what is this technique called?" — which is answerable, non-adversarial, and produces either a name for the comment or the realisation that there isn't one.

Check yourself

What does cyclomatic complexity actually measure?

The number of linearly independent paths through a function — decision points plus one. That is a genuine lower bound on the test cases needed to cover every branch, and it is worth knowing. What it does not measure is readability, which is what it is usually used for.

Why is it a poor readability gate?

Because it cannot see the most common readability refactor there is. Computed from the AST on both versions of the same function, the nested form and the guard-clause form both score 5 — while nesting depth goes from 4 to 1. A function of complexity 12 written as guards reads better than one of complexity 6 nested four deep, and any numeric gate passes the second and blocks the first.

Why do guard clauses help, mechanically?

Each guard discharges its condition and leaves. By the last line of the guarded version the reader holds nothing — every earlier case has already returned, so the final line is unconditional. The nested version demands four conditions held simultaneously at the same point. Same logic, same complexity number, four times the working memory.

Is "extract a method" the same kind of improvement?

Not quite — it relocates the held context rather than discharging it. Pulling an inner block into its own function reduces depth in the caller and creates a new function whose own preconditions are now implicit and unstated. That is often still worth doing; it is a different operation from a guard, and worth distinguishing when you suggest one.

How many copies before you should abstract?

It depends entirely on a variable "DRY" does not mention: how likely the copies are to diverge. Modelled over three years, the breakeven is 2 copies at a 10% divergence risk and 5 at 80% — a 2.5-fold spread. The rule contains no threshold, so applying it as one is applying a number you have not computed.

What is the better review question about duplication?

Not "is this duplicated" but "will these two things change together?" Duplication of things that change together is debt. Duplication of things that merely look alike is the correct answer — and merging them creates a shared abstraction both callers have to fight, which is considerably harder to undo than a copy-paste.

Why is hidden state worse than it looks?

Because it multiplies the test space instead of adding to it. A function with 4 input classes and no hidden state needs 4 cases; one hidden boolean makes it 8, and three make it 32. Nobody writes those 32 — so a function with hidden state is not just harder to test, it is one whose tests are known to be incomplete, with the gap growing exponentially. All six sources break the same property: behaviour is not a function of the arguments.

Ten things to carry forward

  1. Complexity is identical before and after the guard-clause refactor.
  2. It measures independent paths — a lower bound on tests, not a readability score.
  3. Nesting depth caught what complexity missed: 4 against 1.
  4. Depth is the number of conditions a reader holds.
  5. Guards discharge conditions; extraction relocates them.
  6. DRY has no threshold in it — 2 copies or 5, by divergence risk.
  7. Ask whether the two things will change together, not whether they look alike.
  8. Hidden state multiplies the test space: 4 cases become 32.
  9. Argument mutation is invisible at the call site. Look for it hardest.
  10. Ask what the technique is called, not whether it is too clever.

About the measurements

Cyclomatic complexity and nesting depth are computed here by walking the Python syntax tree, not estimated. Both versions of the function are real and the identical score is an output of running the calculator on them.

The models

The comprehension curve and the duplication economics are models, with their parameters exposed as sliders. The duplication conclusion — that the threshold depends on divergence risk — holds across the whole range; the specific copy counts do not.
