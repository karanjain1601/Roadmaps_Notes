SQL

A language people learn by accumulating recipes and then plateau in for years, because the recipes never add up to a model. This unit teaches the model first — sets, the order clauses actually execute in, and what NULL really is — and finds that most of the syntax then explains itself.

How to use this

Chapters 1–4 are the model: sets rather than loops, the logical execution order that explains half of SQL's apparent inconsistencies, three-valued logic, and schema decisions that are expensive to reverse. Chapters 5–8 are how data gets combined, ending with window functions — the feature that removes most of the awkward SQL people write. Chapters 9–11 cover changing data safely. Chapters 12–14 are performance, from indexes through to reading a plan. Chapters 15–16 are production.

Every chapter has a demo that runs real queries against a small in-page dataset — you can watch a join multiply rows, see NULL swallow a comparison, and step through what an index does to a lookup. Examples are PostgreSQL by default, with a note wherever MySQL, SQL Server or SQLite differ in a way that matters. Arrow keys move between chapters.

No prior chapters required. Aimed at someone who can already write a SELECT with a WHERE and wants to stop guessing about everything past that.

Two commitments

Correctness before cleverness

Most SQL bugs are not slow queries — they are queries that return a confidently wrong number. Double-counted rows after a join, a filter that silently drops NULLs, an average over the wrong denominator. Those get more space here than optimisation does.

The database is not a dumb store

Constraints, transactions and set operations exist so that invariants hold even when application code is wrong. Where a job can be done in the database or in application code, this unit says which and why — and it is not always the database.
