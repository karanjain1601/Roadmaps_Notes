The corrected versions, for a shared utilities file TypeScript
// 1. Reject keys that are not on the type.
type StrictOmit<T, K extends keyof T> = Omit<T, K>;
//                        ↑ the whole fix: constrain K

// 2. Distribute over unions, so discriminated unions survive.
type DistributiveOmit<T, K extends PropertyKey> =
  T extends unknown ? Omit<T, K> : never;
//  ↑ `T extends unknown` is a no-op check whose only purpose is to
//    make the conditional distribute (Chapter 12)

// 3. Preserve modifiers, by mapping homomorphically and filtering
//    the keys rather than picking them.
type OmitKeep<T, K extends keyof T> = {
  [P in keyof T as P extends K ? never : P]: T[P]
};
// … except this still has an `as` clause, so it is still not
// homomorphic. Modifiers must be restated. There is no fully
// clean fix in the language today, and that is worth knowing
// rather than discovering.

// The one that IS clean, when you can use it: name the keys you
// want instead of the ones you do not.
type PublicUser = Pick<User, 'id' | 'name'>;
// Pick also loses modifiers, but it fails loudly on a bad key and
// it does not silently accept a typo.

3The function family

Seven utilities, all infer in a different position.

UtilityCaptures
ReturnType<F>The return type. infer after the arrow.
Parameters<F>The parameter list, as a labelled tuple — Chapter 9's connection.
ConstructorParameters<C>Same, from a new signature.
InstanceType<C>What a constructor produces. InstanceType<typeof MyClass> is MyClass.
ThisParameterType<F>The declared this parameter, or unknown.
OmitThisParameter<F>The same signature with this removed — for typing the result of bind.
Awaited<T>The value a promise resolves to, unwrapping nested promises recursively.

Two practical notes. ReturnType<typeof fn> is the everyday form, because ReturnType takes a function type and fn is a value — forgetting typeof is the commonest error with the whole family. And on an overloaded function these utilities see only the last overload, which is a real limitation and a good reason not to build important types on top of an overloaded signature.

4The ones worth writing yourself

Seven absences from the standard library, each a few lines.

A reasonable shared utilities file TypeScript
// Flatten an intersection so the editor shows something readable.
// The single most useful one, and it does nothing to the type.
export type Prettify<T> = { [K in keyof T]: T[K] } & {};

// The counterpart to Readonly, inexplicably missing.
export type Mutable<T> = { -readonly [K in keyof T]: T[K] };

// Make some keys optional, or required, leaving the rest alone.
export type SetOptional<T, K extends keyof T> =
  Prettify<Omit<T, K> & Partial<Pick<T, K>>>;
export type SetRequired<T, K extends keyof T> =
  Prettify<Omit<T, K> & Required<Pick<T, K>>>;

// Keys selected by their value type — Chapters 11 and 13.
export type KeysOfType<T, V> = {
  [K in keyof T]-?: T[K] extends V ? K : never
}[keyof T];

// At least one of a set of keys must be present. Genuinely useful
// for options objects with alternative required fields.
export type RequireAtLeastOne<T, K extends keyof T = keyof T> =
  Omit<T, K> & { [P in K]-?: Required<Pick<T, P>> }[K];

// Exact equality, for type-level tests (Chapter 12).
export type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;

// And the honest advice: before writing a clever one, look at
// type-fest. Most of what you are about to invent is in there,
// already tested against edge cases you have not thought of.

5Check yourself

Five questions.

1. Why does Omit<User, 'nmae'> compile?

Because Omit's second parameter is constrained to PropertyKey, not to keyof T — so any string is accepted and one that matches nothing simply removes nothing. You get the full type back and no error, which means a typo or a key removed during a refactor silently stops having an effect, and the mistake surfaces somewhere else as an unexpected property. The fix is one line: type StrictOmit<T, K extends keyof T> = Omit<T, K>. The loose constraint exists deliberately, so that Omit can be used on union types where a key exists on only some members, but the cost is paid by everyone.

2. What happens when you Omit a key from a discriminated union?

The union collapses. Omit is not distributive, so it computes keyof over the whole union — which yields only the keys common to every member — and produces a single object type from those. A three-member discriminated union comes out as one flat object, the discriminant may survive but the variant-specific fields are gone, and narrowing no longer works. The fix is to make it distribute: T extends unknown ? Omit<T, K> : never, where extends unknown is a no-op check whose only job is to trigger distribution (Chapter 12).

3. Why does Omit lose readonly and ? while Partial keeps them?

Because Partial is homomorphic — { [K in keyof T]?: T[K] } — and Omit is defined via Pick, which maps over a computed key union rather than keyof T directly. Chapter 13's rule: only a mapping written exactly as [K in keyof T] with no as clause preserves the source's modifiers. So a readonly id comes out mutable and an optional name? comes out required-looking, silently. Worth knowing that there is no fully clean fix: even the hand-rolled filtering version needs an as clause and therefore has the same problem.

4. Why is it ReturnType<typeof fn> rather than ReturnType<fn>?

Because ReturnType takes a function type and fn is a value. typeof in a type position is the operator that crosses from the value world to the type world, which is exactly what is needed here — and forgetting it is the commonest error with the whole function family. The related limitation worth remembering: on an overloaded function, ReturnType and Parameters see only the last overload, so building important types on top of an overloaded signature will quietly give you the wrong answer.

5. What is Prettify for, given it does nothing to the type?

Readability of error messages and editor hints. An identity mapping plus & {} forces the compiler to evaluate the type into a flat object literal, so instead of seeing Omit<User, 'id'> & Partial<Pick<User, 'name'>> in a tooltip you see the actual properties. It changes nothing about assignability and costs nothing at runtime, which makes it the highest-value-per-line utility in a shared file — especially on any type built from intersections, where the unexpanded form is genuinely unreadable and turns a simple mismatch into a puzzle.
