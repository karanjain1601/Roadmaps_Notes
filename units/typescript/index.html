TypeScript

Twenty chapters on a type system with two properties that explain everything else: it is erased at compile time, and it compares shapes rather than names. Erasure means a type is a claim about code and never a check on data. Structural comparison means two unrelated things with the same shape are the same type — which is usually convenient and occasionally exactly wrong.

Its relationship to the other units

The Node.js unit covers the runtime this code usually runs on, and the two overlap deliberately at one point: Node's chapter 11 argues that a request body is genuinely any until something checks it, and chapter 13 here explains why that follows from erasure rather than from carelessness. Where a chapter says "chapter 2 of the Node unit", the runtime mechanism lives there. The Front-end Developer and React units are the other main consumers.
