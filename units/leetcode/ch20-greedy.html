Greedy

Take the highest value per unit weight first. That rule is provably optimal for fractional knapsack and 27% below optimal for 0/1 knapsack — the same rule, the same items, and the only difference is whether you may take part of one.

The two properties

A greedy algorithm commits to a locally best choice and never reconsiders. That is only correct when the problem has two properties, and naming them is what separates a proof from a hope.

The greedy choice property
Some optimal solution contains the greedy choice. Not every optimal solution — one is enough, because you can then exchange your way into it.
Optimal substructure
Once the greedy choice is made, solving the remaining subproblem optimally gives an optimal whole. This is the same property dynamic programming needs.

The second is common. The first is what fails, and it fails in a specific way: a greedy choice that constrains the remaining problem more than an alternative would. Chapter 7's earliest-finish rule works precisely because finishing early leaves the largest possible remainder.

On weights 10, 20, 30 with values 60, 100, 120 at capacity 50: fractional greedy gets 240 and that is optimal. The identical rule on 0/1 gets 160 where the optimum is 220 — it takes the two densest items and cannot use the last 20 units of capacity.

Where the exchange argument breaks

For fractional: take any optimal solution containing a unit of lower-density material while higher-density material remains. Swap them. The weight is unchanged and the value cannot fall — so the density order is optimal. Verified on 2,000 random instances.

For 0/1, that swap is unavailable: you cannot exchange part of an item, so the substitution has to fit exactly, and usually it does not. The exchange argument does not merely fail to be found — it is provably unavailable, which is the strongest reason to stop looking for one.

Measured, 0/1 density-greedy is suboptimal on 144 of 2,000 random instances — 7%. That rate is low because small instances often leave no room to do better, and it is exactly the rate that survives testing.

The exchange argument, written out

Chapter 7 used this for activity selection and chapter 4 demanded it for pointer moves. Here it is as a template you can write in an interview in four lines.

proving earliest-finish optimal
1. Let OPT be any optimal solution, and g the greedy first choice.
2. OPT's first interval ends no earlier than g, because g finishes
   earliest of everything available.
3. Replace OPT's first interval with g. Still valid — g ends no later,
   so it conflicts with nothing OPT kept. Still the same size.
4. The remainder is the same problem on a smaller input. Repeat.

Therefore greedy is at least as good as OPT. Since OPT is optimal,
greedy is optimal.

Step 3 is where the argument lives, and it is exactly what fails for 0/1 knapsack: replacing OPT's first item with the densest one may not fit.

All four verified against exhaustive search on 2,000–3,000 random instances each, with no disagreement.

Jump Game's argument is unusually clean

Tracking only the furthest reachable index is enough because reaching index i at all means every index below it was reachable too. There is nothing to remember and nothing to reconsider — the state that a DP would maintain collapses to a single number. When a greedy feels suspiciously simple, look for a collapse like this one; if you cannot find it, the simplicity is probably a bug.

Finding the counterexample in thirty seconds

Proving a greedy correct is hard. Disproving one is trivially easy and almost nobody does it.

Across 200 independent searches for a counterexample to 0/1 density-greedy, one was found every time within 500 tries. The median search needed 8 random instances; the worst needed 66.

The same search run against earliest-finish activity selection examined 200,000 instances and found nothing.

The asymmetry is the whole point

Failing to find a counterexample is not a proof — 200,000 clean instances leave the possibility open. But finding one in eight tries is a complete disproof, and it costs thirty seconds.

So the practical order is: think of the greedy rule, spend half a minute hunting, and only then attempt the exchange argument. Most wrong greedies die in the first dozen instances, and the ones that survive are the ones worth trying to prove.

The sort is usually the algorithm

Most greedy solutions are a sort followed by a single pass, and essentially all the difficulty is in the sort key — chapter 7 measured merge and selection needing opposite keys on the same data.

A low failure rate is the dangerous case

Chapter 7's shortest-first activity selection is wrong on 1.8% of instances. That is not reassuring — it means a handful of hand-written tests will all pass, and the submission fails on a case you never saw. The 35% failures announce themselves; the 2% ones do not.

This is the same profile as chapter 4's unsorted pointers, chapter 15's two-colour cycle detection and chapter 16's Dijkstra with negative edges. Across this unit, rarely wrong and silently wrong has been the dominant failure mode of every plausible-but-unjustified shortcut.

Check yourself

What two properties does a greedy algorithm need?

The greedy choice property — some optimal solution contains the greedy choice, so you can exchange your way into it — and optimal substructure, meaning the remaining subproblem can be solved independently. The second is common and shared with dynamic programming; the first is what fails, and it fails when the greedy choice constrains the remaining problem more than an alternative would.

Why is density-greedy optimal for fractional knapsack and not for 0/1?

Because the exchange is available in one and not the other. For fractional: take any optimal solution using lower-density material while denser material remains, swap a unit, and the weight is unchanged while the value cannot fall — so the density order is optimal. For 0/1 you cannot swap part of an item, so the substitution must fit exactly and usually does not. On weights 10, 20, 30 at capacity 50, greedy gets 160 where the optimum is 220 — it takes the two densest and cannot use the remaining 20 units.

Write the exchange argument for activity selection.

Let OPT be any optimal solution and g the earliest-finishing interval. OPT's first interval ends no earlier than g, since g finishes earliest of everything available. Replace it with g: still valid, because g ends no later and so conflicts with nothing OPT kept, and still the same size. The remainder is the same problem on a smaller input, so repeat. Therefore greedy is at least as good as OPT, and OPT is optimal.

You have a greedy rule and no proof. What do you do first?

Hunt for a counterexample, before attempting a proof. Generate small random instances, run the greedy and a brute force, stop at the first disagreement. Across 200 independent searches against 0/1 density-greedy, one was found every time, with a median of 8 instances and a worst case of 66. Most wrong greedies die in the first dozen; the ones that survive are the ones worth spending proof effort on.

200,000 random instances found no counterexample. Is the greedy correct?

Unproven, not proven. That is exactly what happened with earliest-finish activity selection here — and it is correct, but the search did not establish that. The asymmetry is the point: failing to find a counterexample leaves the question open, while finding one in eight tries is a complete disproof. Use the search to eliminate wrong ideas cheaply, and the exchange argument to establish the surviving one.

A greedy is wrong on 1.8% of inputs. Better or worse than one wrong on 35%?

Worse, in the way that matters. A 35% failure rate announces itself on the first few tests; a 1.8% rate means a handful of hand-written cases all pass and the submission fails on something you never saw. Chapter 7's shortest-first activity selection sits at 1.8%, and it is the more dangerous of the two failures in that chapter for exactly this reason. Across this unit, rarely wrong and silently wrong has been the dominant failure mode of every unjustified shortcut.

What is the quick diagnostic for "greedy or DP"?

Ask whether the choice reduces what you can do later in a way that depends on which choice you made. Earliest-finish leaves the largest possible remainder regardless, so greedy has a chance. Picking a knapsack item consumes capacity that a different item would have used differently, so the alternatives have to be compared — which is dynamic programming. When a greedy feels suspiciously simple, look for a state collapse like Jump Game's, where reaching index i implies reaching everything below it; if you cannot find one, the simplicity is probably a bug.

Ten things to carry forward

  1. Greedy needs the greedy-choice property and optimal substructure; the first is what fails.
  2. The same density rule is optimal fractional and 7% suboptimal for 0/1.
  3. The exchange has to be available, and with indivisible items it usually is not.
  4. The exchange argument is four lines and you can write it in an interview.
  5. Hunt for a counterexample before attempting a proof — median 8 instances, worst 66.
  6. Not finding one is not a proof; finding one is a complete disproof.
  7. The sort key is the algorithm, and the exchange argument is how you choose it.
  8. A 1.8% failure rate is more dangerous than a 35% one.
  9. Ask whether the choice constrains later options differently from the alternatives.
  10. If a greedy feels too simple, look for the state collapse. No collapse, no greedy.
