Chapter 14 · Graphs

Graph traversal patterns

Most graph problems do not hand you a graph. They hand you a grid, a list of pairs, or a set of words — and the first move is always the same: name the vertices, name the edges, and the problem becomes one you already know.

A grid is a graph

Every cell is a vertex. Its edges are the neighbouring cells. That is the entire conversion, and it fits in one array.

the four lines that turn every grid problem into a graph problem
DIRS = [[0,1], [1,0], [0,-1], [-1,0]]

for ([dy, dx] of DIRS) {
    ny = y + dy, nx = x + dx
    if (inBounds(ny, nx) && passable(ny, nx) && !seen[ny][nx]) …
}
// eight-directional? add the four diagonals. hex grid? six offsets.
// the traversal code does not change at all.

Once you see that, Number of Islands, Flood Fill, Max Area of Island, Surrounded Regions, Pacific Atlantic Water Flow and Rotting Oranges are all the same traversal with a different bookkeeping step.

DFS, BFS and union-find all agree on 2,000 random grids. For counting components they cost the same and the choice is stylistic — DFS is shorter to write, BFS avoids recursion depth. Switching to 8-directional connectivity changes nothing but the offsets array, and usually merges several components into one.

DFS cannot answer "shortest"

This is the most consequential distinction in the chapter, and the code for both looks nearly identical.

BFS expands in rings of equal distance

Every cell in the queue at a given moment is the same number of steps from the source. So the first time BFS reaches a cell, it has arrived by a shortest route — no later path can be shorter, because later paths are longer by construction. DFS commits to one direction as far as it goes and returns whatever it stumbles into.

Measured on 3,804 open grids where a path existed, taking the first path DFS finds gives the wrong distance on 667 of them — 18%. That rate is low only because a small grid often has one obvious route; when DFS is wrong it can be badly wrong, and the worst case found reported 24 where the answer is 12.

The rate understates the danger

Eighteen percent is exactly the kind of number that survives testing. A handful of hand-written grids will very likely all have a single corridor, where DFS is correct — and the wrong answers appear on the open cases, which are the ones a generated test suite produces. This is the same failure profile as chapter 4's converging pointers on unsorted input.

The rule has no exceptions worth remembering: unweighted shortest path is always BFS. DFS answers reachability, not distance.

The memory picture is also worth having. On a 200×200 grid with 20% walls, BFS found a shortest path of 399 steps, visiting 32,056 cells with a peak queue of just 185 — one frontier, not the whole grid. BFS costs Θ(width of the frontier), which on a grid is roughly its perimeter rather than its area.

Mark on enqueue, not on dequeue

A small detail with a measurable cost. If you mark a cell visited when you pop it rather than when you push it, then a cell with four unvisited neighbours can be enqueued four times before anyone looks at it.

the one line that matters
if (inBounds && passable && !seen[ny][nx]) {
    seen[ny][nx] = true        // HERE, before the push
    queue.push([ny, nx])
}

Multi-source BFS

"How far is every cell from the nearest source?" looks like it needs one BFS per source. It needs one BFS in total: seed the queue with every source at distance zero.

On a 60×60 grid with 92 sources: multi-source visits 3,600 cells — exactly one per cell — and one BFS per source visits 331,200. A 92-fold reduction, and the ratio is the number of sources, because per-source BFS re-walks the entire grid once for each one.

Why it is correct

With every source at distance 0, the frontier expands from all of them simultaneously. A cell is first reached by whichever source is nearest, so its first-arrival distance is its distance to the nearest source — the same reason single-source BFS gives shortest paths, applied to a set of origins instead of one.

This is the pattern behind Rotting Oranges, 01 Matrix, Walls and Gates, Shortest Bridge and As Far from Land as Possible. Verified identical to per-source BFS on 500 random grids.

Building the graph you were not given

When the input is a list of pairs, the first thing to write is the adjacency list — and the first bug is forgetting that undirected means both directions.

two lines, one of which people omit
adj = array of n empty lists
for ([a, b] of edges) {
    adj[a].push(b)
    adj[b].push(a)        // UNDIRECTED — omit this and the traversal
}                         // still runs and quietly reports the wrong answer

With edges [[1,0],[3,2]] over four vertices, the undirected graph has 2 components. Treating the same list as directed gives 4, because vertices 0 and 2 end up with no outgoing edges at all and each looks isolated. Nothing errors.

Check yourself

How do you turn a grid problem into a graph problem?

Each cell is a vertex; the neighbouring cells are its edges. In practice that is one array — [[0,1],[1,0],[0,-1],[-1,0]] — plus a bounds check and a visited check. Eight-directional connectivity adds the four diagonals and changes nothing else; a hex grid uses six offsets. Once you have written that, Number of Islands, Flood Fill, Max Area of Island, Surrounded Regions and Rotting Oranges are the same traversal with different bookkeeping.

Why can't DFS answer "shortest path"?

Because it commits to one direction as far as it goes and returns whatever it stumbles into first. BFS expands in rings — every cell in the queue at a given moment is the same distance from the source — so the first arrival at a cell is necessarily via a shortest route. Measured on 3,804 open grids, taking DFS's first path gives the wrong distance on 667 of them (18%), and the worst case reported 24 where the answer is 12.

Only 18% wrong. Is that a serious problem?

Yes, and the rate is what makes it serious. A small hand-written grid usually has one obvious corridor, where DFS happens to be right — so the tests you write pass, and the failures show up on open grids, which is what a generated suite produces. It is the same failure profile as chapter 4's converging pointers on unsorted input: frequent enough to be a real bug, rare enough to survive casual testing. Unweighted shortest path is always BFS.

Should you mark a cell visited when you push it or when you pop it?

When you push it. Otherwise a cell with four unvisited neighbours gets enqueued four times before anyone looks at it — measured on a 30×30 open grid, marking on dequeue pushes 1,740 cells against 899 for marking on enqueue, nearly twice the work for the same answer. The overhead scales with the branching factor, so on a general graph with high degree it is considerably worse than 2×.

Every cell needs its distance to the nearest source. How many BFS runs?

One. Seed the queue with every source at distance 0 and let the frontier expand from all of them simultaneously — a cell is first reached by whichever source is nearest, so its first-arrival distance is exactly what you want. On a 60×60 grid with 92 sources, multi-source visits 3,600 cells (one per cell) against 331,200 for one BFS per source: a 92-fold reduction, and the ratio is the source count.

What is the first bug when building an adjacency list from edge pairs?

Forgetting adj[b].push(a) for an undirected graph. The traversal still runs and quietly reports the wrong answer. With edges [[1,0],[3,2]] over four vertices, the undirected graph has 2 components and treating the list as directed gives 4 — because vertices 0 and 2 end up with no outgoing edges and each looks isolated. Nothing errors, which is the recurring theme of this unit's precondition failures.

Word Ladder gives you a word list, not a graph. Now what?

Name the vertices and edges: each word is a vertex and two words are adjacent if they differ by one letter. Then it is BFS for the fewest steps — which is what "shortest transformation sequence" means. The same reframing handles Open the Lock (a combination, one wheel turn), Jump Game III (an index, i ± arr[i]) and Sliding Puzzle (a board state, one legal move). Generate neighbours on demand rather than building the whole adjacency list, since the state space can be enormous.

Ten things to carry forward

  1. A grid is a graph. One offsets array converts every grid problem into a traversal.
  2. For counting components, DFS, BFS and union-find are equivalent — pick by style.
  3. BFS expands in rings, so its first arrival at a cell is via a shortest path.
  4. DFS gives the wrong distance on 18% of open grids, silently, and can overshoot by 2×.
  5. Unweighted shortest path is always BFS. DFS answers reachability.
  6. Mark on enqueue, or you push nearly twice as many cells.
  7. BFS costs Θ(frontier), not Θ(grid) — a peak queue of 185 on a 40,000-cell grid.
  8. Seed the queue with every source and one BFS answers a nearest-source question.
  9. The multi-source saving is the source count — 92 sources, 92× less work.
  10. Name the vertices and edges first. Word Ladder, Open the Lock and Sliding Puzzle are all BFS.
