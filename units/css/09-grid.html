Chapter 9 · Layout systems

Grid

Grid is the layout system where the container decides the sizes. Two things repay measuring: 1fr carries the same automatic minimum that made chapter 8's flex item overflow, and auto-fit and auto-fill are identical until they suddenly are not.

css — the parts worth memorising
grid-template-columns: repeat(auto-fill, minmax(150px, 1fr));   /* responsive, no MQ */
grid-template-columns: repeat(4, minmax(0, 1fr));               /* four equal, safely */
grid-template-columns: 200px 1fr min-content;                   /* mixed is fine     */

/* named areas — the layout is legible in the source */
grid-template-areas: "head head"
                     "nav  main"
                     "foot foot";
.header { grid-area: head }

/* placement by line number, and the span keyword */
grid-column: 1 / 3       ·  grid-column: span 2   ·  grid-column: 1 / -1

/* the one-line overlap: put both children in the same cell */
.stack > * { grid-area: 1 / 1 }      /* no positioning, no z-index needed */

/* subgrid: a child's tracks align with its parent's */
grid-template-columns: subgrid;

The minimum decides how many tracks fit; the 1fr maximum shares out what is left. No media query anywhere.
When grid, and when flex

The useful distinction is not "two dimensions against one" — it is who decides the sizes. In grid the container defines the tracks and every item lands on a line whether or not its neighbours cooperate, which is what you want when things must align across rows: a card grid, a form of labels and fields, a page shell. In flex each item negotiates its own size from its content, which is what you want when the item count varies and alignment across rows is meaningless: a toolbar, a row of tags, a button group. The tell that you chose wrong is fighting the system. A wrapped flex row whose last line has the wrong widths wanted repeat(auto-fill, minmax(…, 1fr)). A grid where you keep writing explicit spans to make things fit probably wanted flex. They also compose: a grid page shell containing flex components is the ordinary arrangement, not a compromise.

Check yourself

Self-check

  1. grid-template-columns: 200px 1fr in a 600px grid. What are the track sizes?
    200px and 400px — measured. fr is a share of the leftover space rather than a percentage of the whole, so fixed tracks are subtracted first and the remainder is divided in proportion to the fr numbers. That makes mixed track lists behave the way you would hope: 200px 1fr 2fr in 800px gives 200, 200, 400. It also means 1fr is not the same as 50% in a two-column grid the moment there is a gap, because the gap is subtracted before the shares are computed while a percentage is not — which is why 50% 50% plus a gap overflows and 1fr 1fr plus a gap does not. Measured, 1fr 1fr gave 300 / 300 and 1fr 2fr gave 200 / 400.
  2. Why did 1fr 1fr produce 308 / 96 instead of 200 / 200?
    Because 1fr is shorthand for minmax(auto, 1fr), so each track has an automatic minimum equal to its content's minimum size — and the first cell held an unbreakable word wider than 200px. Measured, the track refused to shrink below the word and took 308px, leaving 96px for the other. This is precisely chapter 8's flex bug in different syntax: a flex item's min-width: auto and a grid track's minmax(auto, …) are the same rule. The fix is the same shape too — minmax(0, 1fr), measured back to 200 / 200. That is why so much grid code contains what looks like a pointless minmax(0, 1fr) where 1fr would read more simply; the author had met this once.
  3. What is the difference between auto-fit and auto-fill?
    What happens to tracks with nothing in them. Both compute how many tracks fit; auto-fill keeps the empty ones and auto-fit collapses them to zero, after which the 1fr maximum lets the remaining items expand into the freed space. Measured in a 700px grid with minmax(150px, 1fr): at five items both gave 4 tracks of 175px, completely identical — which is why the difference goes unnoticed for years. At two items they diverged sharply: auto-fill left each item at 175px with two empty tracks beside them, and auto-fit stretched each to 350px. So they only differ when there are fewer items than tracks fit, which on a card grid means the last page of results or an empty filter.
  4. Which should a card grid use?
    Usually auto-fill, so that two remaining cards stay card-sized instead of becoming two enormous half-width panels — measured, auto-fit stretched two items from 175px to 350px each. That is almost never what a card design wants, and it is a bug that only appears on the last page of results or when a filter matches two things, so it survives review easily. auto-fit is right when filling the row is the goal and the items have no natural size: a nav bar, a set of equal-weight tabs, a segmented control. A useful middle path is auto-fill with a sensible max-width on the items, or minmax(150px, 300px) as the track, which caps how large a track can get regardless of how few items there are.
  5. How do you overlap two elements in grid without positioning?
    Put them in the same cell: .stack > * { grid-area: 1 / 1 } places every child at row 1, column 1, and they stack in document order with no position and no z-index — which sidesteps chapter 7's stacking contexts entirely. It is the cleanest way to build a hero image with text over it, a card with a badge, or a loading state that fades in over content. Two things it gives you that absolute positioning does not: the container still sizes itself to the largest child, since all of them are in flow, and the normal alignment properties work, so place-self: end puts a badge in a corner without offsets. And because the elements remain grid items, z-index works on them without position — one of the few places that is true.
  6. What does grid-column: 1 / -1 mean?
    From the first line to the last line — a full-width item, whatever the column count. Grid lines are numbered from 1 at the start and from −1 at the end, so -1 is the final line and the negative numbering saves you from hard-coding a count that a media query might change. The caveat worth knowing: negative line numbers only count the explicit grid, so if the item is in an implicitly created column — one grid made for you because content overflowed the template — -1 will not reach it. The related shorthand is span, as in grid-column: span 2, which is relative rather than absolute and therefore survives reordering. Named lines are worth mentioning too: define [content-start] and [content-end] in the template and grid-column: content works by name.
  7. When is flex the better choice?
    When the items should decide their own sizes and alignment across rows does not matter. Flex distributes along one axis with each item negotiating from its content, which suits a toolbar, a row of tags, a button group — anything whose item count varies and whose items have a natural width. Grid defines tracks up front so items align across rows regardless of their neighbours, which suits card grids, forms and page shells. The framing that decides it quickly is who owns the sizes: the container in grid, the items in flex. The tell that you chose wrong is fighting the system — a wrapped flex row whose final line has awkward widths wanted repeat(auto-fill, minmax(…, 1fr)), and a grid full of explicit spans probably wanted flex. And they compose: a grid shell holding flex components is the ordinary arrangement.
