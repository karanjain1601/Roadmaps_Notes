Margin collapse

A 30px margin below one element and a 20px margin above the next produce a gap of 30px, not 50. That much is well known. The case that costs an afternoon is a child's margin-top escaping its parent entirely and moving the parent instead — measured here, along with the six declarations that stop it.

/* collapse exists so that a document of paragraphs spaces evenly: */
p { margin-block: 1em }        /* 1em between paragraphs, not 2em     */
                                /* it was designed for prose, not layout */

/* the modern replacements, in order of preference */
.stack { display: flex; flex-direction: column; gap: 1rem }
.stack > * + * { margin-block-start: 1rem }   /* the "owl", pre-gap  */

/* one-directional margins avoid the whole question */
* { margin-block-start: 0 }
h2 { margin-block-start: 2rem }   /* only ever push DOWN from above */

/* and the property that turns it off entirely, per box */
margin-trim: block;            /* trims a container's first/last child margins */
The parent case, and why it looks like a bug

You give a card's heading margin-top: 40px for breathing room and the whole card moves down 40px instead, with the heading still flush against the card's top edge. Measured exactly: the gap inside the parent was 0px and the parent's own top moved from 0 to 40px. Nothing is broken — the child's top margin and the parent's top margin were adjacent with nothing between them, so they collapsed into one margin belonging to the parent. The tell is that adding a single pixel of padding to the parent fixes it, which no other CSS bug does. It also collapses through several levels: a margin on a deeply nested first child escapes every ancestor with no padding, border or BFC, which is why the effect can appear a long way from its cause.

Check yourself

Self-check

  1. Two stacked elements have margin-bottom: 30px and margin-top: 20px. What is the gap?
    30px — measured. Adjacent vertical margins collapse to the larger of the two rather than summing, which is the case most people know. It exists because CSS was designed for documents: a run of paragraphs each with margin-block: 1em should be separated by 1em, not 2em, and collapse is what makes that work without anyone thinking about it. Two limits worth knowing. It only happens on the block axis — horizontal margins never collapse, so two side-by-side inline-blocks with 30px and 20px are 50px apart. And it only happens in normal flow: measured, the same two margins between flex items gave 50px, because flex and grid simply do not have the rule.
  2. A child has margin-top: 40px and the parent has no padding. What moves?
    The parent. Measured: the gap between the parent's top edge and the child's top edge was 0px, and the parent's own top moved down 40px. The child's top margin and the parent's top margin were adjacent with nothing between them, so they collapsed into a single margin that now belongs to the parent — the margin escaped. This is the case that costs an afternoon, because the symptom (a card that has drifted down the page) is nowhere near the cause (a heading inside it). The tell is that adding one pixel of padding to the parent fixes it, which no genuine bug would. It also collapses through several levels at once: a margin on a deeply nested first child escapes every ancestor that has no padding, border or block formatting context.
  3. What happens to an empty element's own margins?
    They collapse through it. Measured, an empty div with margin-top: 20px and margin-bottom: 30px had a height of 0px and left a gap of 30px between its neighbours — not 50. With no height, no padding, no border and no content, the element's own top and bottom margins become adjacent to each other, collapse into one, and then collapse with whatever is above and below. So the element contributes exactly one margin to the layout, the largest involved. The practical consequence is that an empty spacer div with margins does far less than it looks like it should, and giving it any height, padding or border at all changes the answer completely — which makes it a fragile way to create space.
  4. margin-bottom: 30px meets margin-top: -40px. What is the gap?
    −10px — the elements overlap by ten pixels. Measured. With negative margins the rule is not "take the larger" but "take the largest positive, take the most negative, and add them": 30 + (−40) = −10. The other two measurements confirm the shape — 30 and −20 gave 10px, and −20 and −30 gave −30px, taking the more negative of the two rather than summing them to −50. It follows the same logic as the positive case: each side gets its most extreme claim in each direction, and the results combine. Negative margins are a legitimate tool for overlapping elements and for cancelling a container's padding, though a negative margin that collapses is usually harder to reason about than a transform or a grid overlap.
  5. Name three ways to stop a child's margin escaping, and what each costs.
    All six measured here worked, and they differ only in cost. One pixel of padding or a 1px border on the parent physically separates the two margins so they are no longer adjacent — measured, both put the parent back at 0 and left a 41px gap inside. Cheap, and it changes the visual box very slightly. A block formatting context via overflow: hidden, display: flow-root or display: flex stops collapse through the boundary — with chapter 4's side effects, so flow-root is again the clean one. And flex or grid removes the rule entirely rather than blocking it: measured, two flex items with 30px and 20px gave 50px, summing. That last one is the real modern answer, because gap replaces the margins altogether.
  6. Why does gap avoid the problem instead of solving it?
    Because gap is not a margin. It is a property of the container describing the space between its items, so there is nothing belonging to a child that could escape, collapse or double. It also applies only between items and never on the outer edges, which is the other thing margins get wrong — a list of cards with margin-bottom has a stray margin after the last one that you then have to remove with :last-child. And because it is one declaration on one element, changing the spacing is one edit rather than a hunt through every child rule. The pre-gap equivalent was the "owl" selector, .stack > * + * with a top margin, which gets the between-not-around behaviour right and still uses margins. gap works in flex, grid and multi-column, so there is rarely a reason not to reach for it.
  7. Why does margin collapse exist at all?
    Because CSS was designed for documents, and in a document it is exactly right. A page of paragraphs, headings and lists, each carrying its own margin-block, spaces evenly without anyone coordinating — a heading with 2em below followed by a paragraph with 1em above gives 2em, which is what a typesetter would want. Sum them instead and every author would have to zero one side of every element to avoid compounding gaps. The rule only becomes a problem when the same mechanism is used for layout, where boxes are components rather than prose and you want a spacing you specified to be the spacing you get. That is the historical arc of most CSS awkwardness, and it is why the modern answers — flex, grid, gap — do not extend collapse into the new layout modes but simply omit it.
