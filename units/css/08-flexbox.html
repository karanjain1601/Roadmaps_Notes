Flexbox

Two things account for most flexbox confusion. flex: 1 and flex: auto look interchangeable and produce 300px / 300px against 156px / 445px on the same content. And a flex item's minimum size is auto, not zero — measured, one stayed 617px wide inside a 300px container.

The flex shorthand

Two items of different length in a 600px row
Compare flex: 1 with flex: auto
flex: 1 is 1 1 0% — content is ignored
Measured: both items came out at 300px despite one being far longer. The basis of zero means every item starts from nothing and the free space is split evenly.

That single character is the whole difference
"Equal columns" means flex: 1. "Proportional to content, filling the row" means flex: auto.
The default is 0 1 auto

Why items refuse to shrink

flex-basis beats width on the main axis

The nested-flex overflow, and why it is the same bug

The version you will actually meet is not a long word — it is a flex container inside a flex container, where the inner one holds text that should truncate with text-overflow: ellipsis and instead pushes the whole layout wider than the window. Same cause: the inner container is itself a flex item, its automatic minimum size is the minimum size of its own content, and no amount of flex: 1 changes that. The fix is min-width: 0 on every level between the overflowing text and the container that should constrain it, which is why it so often takes three attempts — fixing the innermost one alone does nothing. On a column-direction container the property is min-height: 0 instead, and forgetting that is why a scrollable panel inside a flex column grows instead of scrolling. Worth adding min-width: 0 alongside flex: 1 as a habit.

Check yourself

Self-check

  1. flex: 1 and flex: auto — what is the difference?
    The basis. flex: 1 expands to 1 1 0% and flex: auto to 1 1 auto, so the only difference is where each item starts before the free space is shared. With a basis of zero, content is ignored entirely and every item gets an equal share — measured, both items came out at 300px despite one holding far more text. With a basis of auto, items start at their content size and share only the leftover, which measured 156px and 445px on identical markup. So "make these columns equal" is flex: 1, and "fill the row but keep the proportions" is flex: auto. The two are constantly used interchangeably and produce visibly different layouts the moment the content lengths differ.
  2. Why does a single number in flex also change the basis?
    Because the specification defines the one-value form that way: flex: <number> sets grow to that number, shrink to 1, and basis to 0% — measured as 1 1 0% for flex: 1. It is deliberate, because the common case for "grow" is equal or proportional columns, and that only works from a zero basis. It surprises people because the number looks like it should only affect growth. The consequence worth remembering is that flex: 2 and flex: 1 together give a genuine 2:1 split of the whole row, whereas flex-grow: 2 and flex-grow: 1 with the default auto basis split only the leftover in 2:1, giving a ratio that depends on the content. If you want the second behaviour, write the longhand and the intent is visible.
  3. A flex item with flex: 1 overflows its container. Why?
    Because a flex item's min-width computes to auto, not 0, so it refuses to shrink below its content's minimum size — measured, an item stayed 617px wide inside a 300px container, overflowing by 317px. flex: 1 does not help, because the shorthand sets grow, shrink and basis and says nothing about the minimum. This exists so that content does not get silently crushed to nothing, which is reasonable as a default and is the single commonest flexbox bug. The fixes measured: min-width: 0, overflow: hidden or overflow: auto all brought it to 298px — any overflow other than visible works, because a scroll container has no automatic minimum. On a column-direction container the property is min-height: 0.
  4. You set width: 200px on a flex item and nothing happens. Why?
    Most likely flex-basis is overriding it. On the main axis flex-basis takes precedence over width — measured, width: 100px together with flex-basis: 300px produced 300px. And since flex: 1 silently sets the basis to 0%, writing flex: 1; width: 200px means the width is ignored and the item is sized entirely by growth. The other possibility is that the item is growing or shrinking past your width, since the default flex-shrink is 1: a 200px item in a crowded row will shrink below 200 unless you say flex-shrink: 0. If you want an exact size, flex: none — which is 0 0 auto — plus a width, or simply flex: 0 0 200px, states it unambiguously in one declaration.
  5. What is the default flex value, and what does it imply?
    0 1 auto — measured as the computed value with no flex declared. Do not grow, do shrink, start from content size. That combination explains two things people notice immediately. Flex items do not fill their container by default, because grow is 0 — which is why the first thing everyone writes after display: flex is flex: 1 on something. And they do get squashed when space runs short, because shrink is 1, which is why a row of buttons compresses awkwardly on a narrow screen until someone adds flex-shrink: 0 or lets the row wrap. The two named shortcuts are worth knowing for exactly these cases: flex: none is 0 0 auto, rigid in both directions, and flex: auto is 1 1 auto, flexible in both.
  6. When should you reach for grid instead?
    When the layout is two-dimensional, or when the container should decide the sizes rather than the items. Flexbox distributes space along one axis and each item negotiates its own size, which is exactly right for a toolbar, a row of tags, or anything whose item count varies. Grid defines the tracks up front, so every item lands on a line whether or not its neighbours cooperate — which is what you want for a page layout, a card grid that must align across rows, or a form where labels and fields line up in columns. The tell that you have chosen wrong is fighting: a wrapped flex row where the last row's items are the wrong width wants grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)), and a grid where you are constantly setting explicit spans probably wanted flex.
  7. Which properties go on the container and which on the items?
    The container owns the axis and the distribution: flex-direction, flex-wrap, gap, justify-content for the main axis, and align-items and align-content for the cross axis. The items own their own flexibility: flex and its three longhands, order, and align-self to opt out of the container's cross-axis alignment. The reliable mnemonic is that justify- is always the main axis and align- is always the cross axis, which stays true when you flip flex-direction: column and the two swap physical meaning — that swap is what makes people think the properties are unpredictable. And note order changes only the visual sequence, not the DOM: tab order and screen-reader order still follow the markup, which chapter 21 treats as an accessibility problem rather than a feature.
