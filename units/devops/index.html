DevOps

Twenty-four chapters on the machinery between a commit and a running system that people depend on. The Linux box, the shell you drive it with, the network it sits on, the container you package into, the scheduler that places it, the code that provisions the infrastructure, the pipeline that ships it, and the instrumentation that tells you it is still working. The models run live in the page — find the deploy frequency that minimises downtime, watch a queue explode at ninety per cent utilisation, break a pipeline with an unquoted variable, watch the OOM killer choose its victim.

What this unit is trying to replace

The DevOps roadmap is mostly a list of product names, which is the least useful part of it. Tools are the surface: nginx, Terraform, Ansible, Prometheus and their competitors are interchangeable expressions of about a dozen underlying ideas — a reverse proxy, a declarative desired state with a reconciliation loop, an idempotent convergence run, a time-series database with a pull model. This unit teaches the dozen ideas properly and then names the tools that implement them, so that a tool you have never seen becomes a matter of syntax rather than concept.

Where a topic has its own unit on this site — Docker, Kubernetes, Terraform, AWS, Linux, Git — this unit covers the part a generalist operator needs and says plainly where the deep dive lives. It does not assume you have read them.

How the chapters are built

Every chapter opens with the problem before the solution, gives you the mechanism rather than the command list, and carries two interactive models wired to real arithmetic — no illustrative fake numbers. Each closes with a set of self-check questions with full answers and a ten-point recap. Code is copyable. Nothing here needs a server, a network or a build step: the folder works from a USB stick.
