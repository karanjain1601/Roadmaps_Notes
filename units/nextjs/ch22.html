1How to use this

Four tools, each for a different moment.

The checklist, before a launch
Fifty-four items grouped by part, each with the chapter that explains it. Work down it once before real traffic and again before anything significant. Ticks are not saved between visits, which is deliberate — it is a review, not a record.
The lookup, when something is odd
Thirty-six symptoms in the words you would actually use. Search it for the phrase you would type into a chat message and it will name the mechanism.
The glossary, while reading anything else
A hundred and twenty-seven terms. Most of the difficulty in Next is vocabulary that sounds interchangeable and is not — cache and memoisation, static and prerendered, dynamic and interactive.
The quiz, to find your gaps
Thirty-four questions scored per part, so a weak part points at chapters rather than at a general feeling.

6Where to go from here

Four directions, depending on what you are missing.

If the rendering and data chapters felt shaky
Build something small with a genuine mixture: a public page that must stay static, a dashboard that must not, and a mutation that has to invalidate both. Chapters 8 to 12 only really land once you have watched the build output change under your own hands.
If React itself is the gap
The React unit in this catalogue covers hooks, re-renders, forms, server components and testing in depth. This unit assumes it and does not repeat it.
If the platform layer is the gap
The Front-end Developer unit for browsers, CSS and performance measurement; the Back-end unit for HTTP, caching, auth and database work — which is where most of a Next application's real complexity lives once the framework stops being the hard part.
And keep checking the version
Chapter 10 said it and it applies to the whole unit: the layers, the boundaries and the trade-offs are stable; the defaults and the API names have moved and will move again. Learn the model, state your intent explicitly, and read the documentation for the version you are actually on.
