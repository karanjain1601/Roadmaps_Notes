Elasticsearch

A search engine that accepts JSON, speaks HTTP and answers fast enough to feel like a database — which is exactly how people get into trouble with it. Underneath is an inverted index that made one specific trade: it will find things by their contents at extraordinary speed, and it will not promise you a consistent read.

How to use this

One prerequisite: you should be comfortable with JSON and with making HTTP requests. Everything in Elasticsearch is a JSON document sent to a URL, so if curl -XPUT and a nested object are familiar, you have enough. Having used a database helps for the comparisons — the PostgreSQL and MongoDB units are referenced where the contrast is instructive — but nothing here depends on them.

Chapters 1–3 are the model, and chapter 3 is the one to read twice: almost every surprising search result in Elasticsearch traces back to what analysis did to your text before it was ever indexed. Chapters 4–6 are modelling, including the array trap that silently returns wrong answers. Chapters 7–11 are searching, 12–13 are the analytics half nobody mentions, and 14–18 are running it — ending with the cases where Postgres would have been the better answer.

Demos run real logic — you can watch an analyzer chain turn a sentence into terms, see why a term query on an analysed field returns nothing, compare BM25 scores across documents, and watch a nested query find what a flattened object cannot. Examples target Elasticsearch 8 and 9, and note where behaviour changed.

Two commitments

Why, before how

Elasticsearch is very easy to use badly, because it accepts almost anything you send and returns something plausible. Most chapters start with the mechanism — the inverted index, the analyzer, the shard — because knowing what is happening underneath is what separates a query that works from one that works by accident.

Honest about the sharp edges

It is not a system of record. Nested arrays flatten in a way that returns wrong results with no error. Shard counts are close to permanent. Aggregations on high-cardinality fields are approximate. The licence changed and there is a fork. All of that is in here rather than in a footnote.
