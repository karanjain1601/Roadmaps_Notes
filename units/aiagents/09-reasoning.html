Reasoning and planning patterns

Every named pattern in this chapter is a different answer to one question: how much should the agent think before it acts, and how much should it commit to in advance? The answers differ mainly in what they cost, which is how they should be chosen.

react plan-execute replanning tree search reflection

The spectrum

PatternCommits toAdaptsExtra calls
ReAct — reason and actOne step at a timeContinuouslyNone
Plan and executeThe whole plan, up frontNot at all+1
Plan, execute, replanThe next few stepsAt checkpoints+1 per replan
DecompositionA set of subtasksWithin each subtask+1, plus a run per subtask
Tree of thoughtNothing — explores branchesBy backtracking×3 to ×10
ReflectionAn answer, then revises itOnce, after the fact+2 per round
Most production agents should be ReAct with a first-step plan

That is the honest summary of this chapter. Ask the model to sketch an approach on step one — it improves the whole trajectory and gives you something to show the user and to log — then let it proceed one step at a time, adapting. The elaborate patterns below earn their cost in specific, recognisable situations, and are a liability outside them.

ReAct

Interleave reasoning with action. The model states what it is thinking, calls a tool, reads the result, thinks again. Native tool calling does this implicitly; making the reasoning explicit still helps on hard tasks and helps enormously when reading traces.

encouraging explicit reasoning without a special format
# Modern models emit reasoning alongside tool calls if you ask for it in the
# system prompt. You rarely need the classic Thought/Action/Observation parser.

SYSTEM += """
Before each tool call, state in one sentence what you are trying to establish
and why this tool answers it. If a result surprises you, say so and explain how
it changes your approach.
"""

# The value is threefold:
#   1. quality - a stated intention constrains the choice that follows
#   2. debugging - traces become readable, and wrong turns become explicable
#   3. UX - the sentence is what you stream to the user as progress
#
# The cost is ~40 output tokens per step. On a 10-step run at workhorse pricing
# that is well under a cent, and it is the best value in this chapter.

Planning up front

A plan written before any action is coherent, inspectable and easy to approve. It is also written in ignorance of everything the tools are about to reveal — which is why pure plan-and-execute fails in exactly the situations that justified using an agent.

plan.py — plan, execute, and replan when reality diverges
class Plan(BaseModel):
    goal_restated: str
    steps: list[str] = Field(max_length=8, description="Each step one action")
    unknowns: list[str] = Field(description="What you do not yet know that could change this")
    done_when: str = Field(description="Objective, checkable completion criterion")

PLAN_PROMPT = """Plan how to accomplish this task with the tools available.
Do not call any tools yet.

Task: {goal}
Tools: {tool_summaries}

Keep it to the fewest steps that would actually work. List what you do not know
that might invalidate the plan. State a completion criterion someone else could
check."""

def run_planned(goal, ctx, tools, budget):
    plan = structured_call(Plan, PLAN_PROMPT.format(...))
    emit_progress(plan)                             # show it; log it; maybe approve it

    messages = base_messages(goal, plan)
    for n in range(budget.max_steps):
        reply = step(messages, tools)
        ...
        # Replan when the world disagrees with the plan, not on a timer.
        if diverged(reply, plan):
            plan = structured_call(Plan, REPLAN_PROMPT.format(
                original=plan, learned=recent_findings(messages)))
            messages.append({"role": "user",
                             "content": f"Revised plan:\n{render(plan)}"})

def diverged(reply, plan) -> bool:
    return (reply.tool_error                        # a step failed
            or reply.mentions_surprise              # the model said so
            or reply.tool not in expected_tools(plan))   # it went off-plan
The plan is worth having even when you ignore it

Even in a pure ReAct agent, generating a plan on step one pays for itself. It gives the user visible structure instead of a spinner, it gives you a diff when a run goes wrong ("it planned four steps and took eleven — why?"), and it creates a natural human approval point before anything executes. Treat it as an artefact of the run rather than a schedule the agent must follow.

Search: tree of thought and its relatives

Instead of committing to one line of reasoning, generate several, evaluate them, and pursue the best — backtracking when a branch fails. Genuinely powerful for problems with a large solution space and a cheap way to score a candidate.

RequirementWhy
A scoring functionWithout one, "evaluate the branches" is another model call with no ground truth, and the search wanders. Tests passing, a constraint satisfied, a numeric objective — something real
Cheap, reversible stepsYou cannot backtrack a sent email or an issued refund. Search is for exploration, not for actions with side effects
A large branching factor that mattersIf there are two plausible approaches, just try one. Search pays when there are many and most are wrong
Budget for 3–10× the costThis is the honest multiplier. Decide whether the problem is worth it before building it

DAG agents

Some tasks decompose into subtasks with a known dependency structure: three lookups that are independent, then a synthesis that needs all three. Expressing that as a directed graph rather than a linear loop gets you parallelism for free and makes the structure testable.

a graph where the shape is known, agents where it is not
import asyncio

async def billing_investigation(order_ref: str, ctx) -> Report:
    # Level 1 - independent, run concurrently. No agent needed: the steps are known.
    order, payments, policy = await asyncio.gather(
        get_order(order_ref, ctx),
        list_payments(order_ref, ctx),
        search_policy("duplicate charge refund", ctx),
    )

    # Level 2 - depends on level 1, and here the path genuinely varies.
    if looks_anomalous(payments):
        finding = await run_agent(
            goal=f"Determine why order {order_ref} has {len(payments)} captures "
                 f"and what remedy the policy requires.",
            ctx=ctx.with_facts(order=order, payments=payments, policy=policy),
            budget=Budget(max_steps=6))
    else:
        finding = Finding.no_anomaly(order, payments)

    return compose_report(order, payments, policy, finding)

# The lesson: use a graph for the parts whose shape you know, and an agent only
# for the parts whose shape you do not. Most real tasks are mostly known shape
# with one genuinely uncertain region in the middle.

Reflection

Produce an answer, critique it, revise. Real gains on writing and code; roughly doubles cost, and the second round of critique adds almost nothing over the first.

reflect.py — one round, with concrete criteria
CRITIQUE = """Review this draft against the criteria. For each, decide pass or fail
and quote the specific text that fails. Do not rewrite it.

{goal}
{draft}

Criteria:
{criteria}

If everything passes, say PASS and nothing else."""

def with_reflection(goal: str, criteria: list[str], ctx) -> str:
    draft = generate(goal, ctx)

    critique = model.complete(CRITIQUE.format(goal=goal, draft=draft,
                                              criteria=bullet(criteria)),
                              temperature=0).text
    if critique.strip().startswith("PASS"):
        return draft                                  # ~40% of the time, in practice

    return model.complete(
        f"Revise the draft to address every point raised. Change only what the "
        f"critique identifies.\n\n{draft}\n{critique}",
        temperature=0).text

# Two things make this work rather than produce circular self-congratulation:
#   - explicit criteria, so the critique has something to check against
#   - the critique must quote failing text, so it cannot be vague approval
# Without both, a model asked to critique its own output mostly says it is good.
Self-critique without criteria is theatre

"Review your answer and improve it" produces a longer answer, not a better one. Models are poor at spotting their own factual errors and good at adding qualifications, so unguided reflection reliably increases length and confidence while leaving mistakes in place. The version that works has named criteria, demands quoted evidence for each failure, and permits a clean PASS. If you cannot write the criteria, reflection is not the tool you need.

Choosing

Can you enumerate the steps?Yes → write a chain or a DAG. Not an agent at all
↓
Does the path depend on findings?Yes → ReAct with a first-step plan. This is the default and covers most cases
↓
Are there many candidate solutions and a real verifier?Yes → search, and budget 3–10× the cost
↓
Is quality subjective and improvable by critique?Yes → one round of reflection against written criteria
↓
Are there independent subtasks producing a lot of noise?Yes → decompose into isolated sub-runs (chapter 10)
  • Add one pattern at a time and measure. Teams routinely stack planning, reflection and search, then cannot say which helped. Chapter 13 is the measurement.
  • Count the multiplier before building. A pattern that triples cost needs to triple something you care about.
  • Patterns do not fix bad tools. If the agent picks wrong tools, more reasoning produces better-argued wrong choices. Fix chapter 4 first.
  • Log the plan and the critique as first-class trace events. They are the most readable explanation of why a run went the way it did.
  • Prefer structure you wrote over structure the model improvises. A DAG you can test beats an agent that usually gets the order right.

The short version

  1. Every pattern answers one question: how much to think before acting, and how much to commit to.
  2. The default that fits most production agents is ReAct with a plan generated on step one.
  3. Explicit reasoning costs about forty tokens a step and pays back in quality, readable traces and streamable progress.
  4. A plan written before any tool call is ignorant by construction. Replan when reality diverges, not on a timer.
  5. Search needs a real scoring function and reversible steps, and costs 3–10×. Without both, it wanders expensively.
  6. Use a DAG for the parts whose shape you know, and an agent only for the uncertain region.
  7. Reflection works with named criteria and quoted evidence; without them it makes answers longer, not better.
  8. Add one pattern at a time and measure. Patterns cannot compensate for badly described tools.
