Evaluating agents

Evaluating a single call is hard. Evaluating an agent is harder, because the same task can be completed by several legitimate routes, the environment changes underneath you, and a run that reached the right answer by six wasteful steps is not really a success.

outcome trajectory simulation metrics ci

Two things to measure

Outcome

Did the task get done? Objective, business-relevant, and the number your stakeholders care about.

Blind to how. A run that succeeded by luck, at four times the cost, scores identically to a clean one — and will fail next week.

Trajectory

How did it get there? Which tools, in what order, how many steps, what was retried.

Diagnostic. Tells you why the outcome number moved, and catches fragility before it becomes failure.

Score the outcome, diagnose with the trajectory

Do not grade against a single "correct" trajectory — there are usually several valid routes, and penalising a good one you did not anticipate makes your eval set actively misleading. Instead: pass or fail on the outcome, then track trajectory properties — step count, tool accuracy, retries, whether any unsafe action was attempted. Those properties are where the early warnings live.

Simulating the world

The distinctive problem: an agent acts on things. You cannot evaluate against production, and you cannot evaluate against a moving staging environment either — the same task would pass on Monday and fail on Thursday for reasons unrelated to your change.

world.py — a fixture-backed world your tools run against
class World:
    """In-memory, deterministic, resettable. Tools talk to this in evals."""
    def __init__(self, fixture: str):
        data = json.load(open(fixture))
        self.orders    = Table(data["orders"])
        self.payments  = Table(data["payments"])
        self.customers = Table(data["customers"])
        self.policies  = Table(data["policies"])
        self.proposals = Table([])            # starts empty; the agent fills it
        self.refunds   = Table([])
        self.emails    = Table([])
        self.calls: list[tuple[str, dict]] = []      # everything the agent did

    def snapshot(self) -> dict:
        return {"proposals": len(self.proposals), "refunds": len(self.refunds),
                "emails": len(self.emails)}


# Failure injection is a first-class feature, not an afterthought.
class FlakyWorld(World):
    def __init__(self, fixture: str, fail: dict[str, str]):
        super().__init__(fixture)
        self.fail = fail             # {"list_payments": "timeout", "search_policy": "empty"}

    def call(self, tool: str, args: dict):
        mode = self.fail.get(tool)
        if mode == "timeout":  raise ToolTimeout(tool)
        if mode == "empty":    return []
        if mode == "garbage":  return {"unexpected": "shape"}
        return super().call(tool, args)
Fixtures make the eval fast, free and honest

With an in-memory world, a hundred-task suite runs in the time the model calls take and costs only those calls — no network to your own services, no shared staging database, no cleanup, no flakiness from someone else's deploy. It also lets you assert on state rather than only on text: "a proposal exists and no refund was issued" is a far stronger check than looking for words in an answer. Build the world before the task set; everything else gets easier.

Judging a trajectory

Some things resist assertions: was the approach sensible, did it explain itself, did it give up too early. A judge helps, provided you ask it about properties rather than for a grade.

Non-determinism

One run of a task is a sample, not a result

Agents are non-deterministic even at temperature 0, and the variance compounds over steps. A task that passes once may pass 60% of the time. Run each task three times and record the pass fraction; treat anything below 3/3 as a partial pass and investigate. Compare versions on the aggregate across all runs, and be honest about the confidence interval — with 50 tasks, a 4-point difference is noise.

run_evals.py — repeats, parallelism, and a stored report
REPEATS = 3

async def run_suite(tasks: list[AgentTask], config: Config) -> Report:
    sem = asyncio.Semaphore(8)

    async def one(task: AgentTask, attempt: int):
        async with sem:
            world = World(task.fixtures)                    # fresh world per attempt
            run = await run_agent(task.goal, ctx_for(world, config),
                                  tools=tools_for(config),
                                  budget=Budget(max_steps=task.max_steps,
                                                max_cost_usd=task.max_cost_usd))
        return score(task, run, world, attempt)

    rows = await asyncio.gather(*[one(t, i) for t in tasks for i in range(REPEATS)])

    report = Report(
        run_id=now_iso(),
        config=config.as_dict(),          # model, prompt version, tool set, budgets
        config_hash=hash_config(config),
        rows=rows,
    )
    report.save(f"evals/reports/{report.run_id}-{report.config_hash}.json")
    return report


def score(task, run, world, attempt) -> dict:
    outcome = (all(check(world) for check in task.expect_state)
               and all(s.lower() in run.text.lower() for s in task.answer_contains)
               and not any(s.lower() in run.text.lower() for s in task.answer_excludes))
    tools_used = [s.tool for s in run.steps if s.tool]
    return {
        "task": task.id, "attempt": attempt, "category": task.category,
        "success": outcome,
        "steps": len(run.steps),
        "cost": run.cost,
        "first_tool_ok": (tools_used[:1] == [task.expect_first_tool]
                          if task.expect_first_tool else None),
        "unsafe_attempt": any(t in task.forbidden_tools for t in tools_used),
        "halted": run.status == "halted",
        "trace_id": run.trace_id,
    }

In CI

gate.py — tolerance on quality, none on safety
TOLERANCE = 0.03            # run-to-run noise on a 100-task suite

def gate(curr: Report, base: Report) -> None:
    fail = []

    if curr.success_rate < base.success_rate - TOLERANCE:
        fail.append(f"success {base.success_rate:.2f} → {curr.success_rate:.2f}")

    # Safety is not subject to tolerance.
    if curr.unsafe_attempts > 0:
        fail.append(f"unsafe attempts: {curr.unsafe_task_ids}")
    if curr.slice(category="adversarial").success_rate < 1.0:
        fail.append(f"adversarial failures: {curr.slice(category='adversarial').failed_ids}")

    # Efficiency regressions matter even when success holds.
    if curr.median_steps > base.median_steps * 1.3:
        fail.append(f"median steps {base.median_steps} → {curr.median_steps}")
    if curr.cost_per_success > base.cost_per_success * 1.4:
        fail.append(f"cost/success +{curr.cost_per_success/base.cost_per_success-1:.0%}")

    if fail:
        raise SystemExit("Agent eval gate failed:\n  " + "\n  ".join(fail))
  • Run the full suite on prompt changes, tool changes and model upgrades. All three change agent behaviour, and only the third is obvious.
  • Run a fast subset on every commit — twenty tasks, no repeats, adversarial cases included. Ninety seconds, catches most breakage.
  • Store the config with every report. Comparing runs without knowing the model, prompt version and budgets is comparing nothing.
  • Slice by category always. An overall 0.74 hiding 0.95 on lookups and 0.35 on investigations is a different problem from a uniform 0.74.
  • Promote production failures into the suite. Every incident becomes a task with the fixtures that reproduce it.
  • Track cost and steps alongside success. A change that adds three points and doubles cost is a decision, not a win.

The short version

  1. Score the outcome, diagnose with the trajectory. Never grade against one "correct" route — several are usually valid.
  2. Build an in-memory fixture world first. It makes evals fast, free, deterministic, and lets you assert on state rather than text.
  3. Failure injection is a feature of that world, not an afterthought. Degraded tasks measure graceful failure.
  4. Cost per success is the number to decide on; step-count p95 is the early warning.
  5. Unsafe attempts count even when blocked. The guard caught it this time.
  6. Run every task three times. One run is a sample, and 3/3 is the only real pass.
  7. Judge trajectories on specific properties with cited steps, and validate the judge against your own labels first.
  8. In CI: tolerance on quality, zero on adversarial and unsafe, and gate on efficiency regressions too.
