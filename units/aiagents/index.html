AI Agents

An agent is a loop that fits in forty lines. Everything hard about agents is what happens on step nine of a run that should have stopped at step four — and what that run was allowed to touch on the way. This unit is about the forty lines, and then about all of that.

How to use this

Chapters 1–3 build a working agent with no dependencies so that every abstraction you meet later has something concrete underneath it. Chapters 4–6 are tools, which is where most of the real engineering lives. Chapters 7–8 cover the window and what persists beyond it. Chapters 9–11 are the architectures people argue about, assessed by what they cost. Chapters 12–16 are the difference between a run that impresses you once and a system you can leave switched on.

Every chapter has a demo that computes rather than pretends: a loop you can run with the guards off, a context window you can watch fill, a permission model whose blast radius you can inspect. Code is Python and TypeScript. Arrow keys move between chapters.

This unit assumes you can already get a model to answer well in your own code. If not, read the AI Engineer unit first — chapters 4 to 7 in particular.

Where this overlaps, and what is elsewhere

Calling models, prompting, RAG

The AI Engineer unit covers the API surface, tokens and cost, prompt structure and retrieval end to end. This unit assumes all of it and goes deeper only where agents change the answer.

Attacking models

Chapter 15 is defensive: what an agent lets an attacker reach. Offensive technique, jailbreak taxonomy and red-team methodology belong to the AI Red Teaming unit.

Running GPUs

Self-hosting an open model to serve an agent is an MLOps problem once it grows past one box. Model choice for agentic work is chapter 3; the cluster is not here.
