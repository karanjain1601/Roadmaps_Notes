Stacks and queues

Two structures defined not by how they store things but by which end you are allowed to touch. That restriction is the point — it makes the implementation trivial, the cost constant, and a whole family of problems suddenly straightforward.

The stack

Last in, first out. You may add to the top, remove from the top, and look at the top. Nothing else.

The call stack is a stack

Every function call pushes a frame holding its locals and return address; every return pops one. That is why recursion depth is bounded, why a stack overflow is called that, and why a traceback reads bottom-up — it is printing the stack. Chapter 7 makes this explicit, and any recursive algorithm can be rewritten iteratively by managing that stack yourself.

python — bracket matching, the archetype
def balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False          # wrong closer, or nothing open
    return not stack                  # anything left open is unbalanced
    # O(n) time, O(n) space

The queue

First in, first out. Add at the back, remove from the front. The obvious implementation is the wrong one.

Why a plain array queue is broken

Using append to enqueue and pop(0) to dequeue looks correct and is O(n) per dequeue, because every remaining element shifts left one position. Processing n items becomes O(n²). This is the single most common accidental quadratic in breadth-first search code. The fix is a circular buffer: keep the array fixed and move the front and back indices instead of the data.

Circular buffer
Nothing shifts — only the two indices move
python — a circular buffer, explicitly
class RingQueue:
    def __init__(self, capacity):
        self.buf = [None] * capacity
        self.head = 0          # where the next dequeue reads
        self.size = 0          # tracking size avoids the full/empty ambiguity

    def enqueue(self, x):
        if self.size == len(self.buf):
            raise IndexError("full")      # or grow and re-lay-out
        self.buf[(self.head + self.size) % len(self.buf)] = x
        self.size += 1                       # O(1)

    def dequeue(self):
        if not self.size:
            raise IndexError("empty")
        x = self.buf[self.head]
        self.buf[self.head] = None            # release the reference
        self.head = (self.head + 1) % len(self.buf)
        self.size -= 1
        return x                            # O(1) — nothing moved

# in practice, just use the standard library:
from collections import deque
q = deque()
q.append(x)        # enqueue — O(1)
q.popleft()        # dequeue — O(1)
q.appendleft(x)    # and it works at both ends
q.pop()

Deques and priority queues

Deque
A double-ended queue: O(1) insertion and removal at both ends. It subsumes both the stack and the queue, which is why Python offers one structure rather than three. Also the right tool for sliding-window problems that need to discard from both ends — chapter 19.
Priority queue
Removes the highest priority element rather than the oldest or newest. Not a queue in the FIFO sense at all. Implemented with a heap, giving O(log n) insertion and removal — chapter 13.
Circular buffer as a fixed-size window
Overwrite the oldest entry when full, and you have a ring log or a rolling buffer of the last n events. Used everywhere in audio, telemetry and networking.

The monotonic stack

One of the highest-value patterns in this unit. Keep a stack whose values are always in sorted order, popping anything that breaks the order — and a family of problems that look quadratic collapses to a single linear pass.

The signal to reach for it: "for each element, find the nearest element to its left or right that is greater or smaller". Next greater element, daily temperatures, largest rectangle in a histogram, trapping rain water, stock spans — all the same shape.

Next greater element
One pass, and every index enters and leaves the stack exactly once
python
def next_greater(a):
    res = [-1] * len(a)
    stack = []                        # holds INDICES, values decreasing bottom to top
    for i, x in enumerate(a):
        while stack and a[stack[-1]] < x:
            res[stack.pop()] = x      # x is the answer for everything smaller
        stack.append(i)
    return res
    # O(n) — each index is pushed once and popped at most once,
    # so the inner while loop runs n times in total across the whole outer loop
Why the nested loop is still O(n)

A while inside a for looks quadratic, and here it is not. Each index is pushed exactly once and can be popped at most once, so the total number of pop operations across the entire run is bounded by n regardless of how many happen on any single iteration. This is an amortised argument of exactly the kind in chapter 2 — count the total work over the sequence, not the worst case of one step.

Self-check

  1. Why is list.pop(0) the wrong way to dequeue?
    Removing from the front of a contiguous array requires shifting every remaining element left one position, so it is O(n). Processing n items becomes O(n²). A circular buffer keeps the data still and advances an index instead, making it O(1) — and collections.deque does exactly that for you. This mistake is most common inside breadth-first search, where the queue is the whole algorithm.
  2. How do you tell a full circular buffer from an empty one?
    You cannot from the indices alone — in both cases head equals tail, which is the classic ambiguity. Three fixes: store the size explicitly (simplest and what the code above does); leave one slot permanently unused so full means tail is one behind head; or keep a boolean flag. Every real ring-buffer implementation picks one of these, and forgetting to is a genuine source of bugs.
  3. A monotonic stack solution has a while inside a for. Why is it not O(n²)?
    Because each index is pushed once and popped at most once, so the total number of iterations of the inner loop across the entire run is bounded by n. A single outer iteration might pop many items, but that work was paid for by the pushes that put them there. Counting the total rather than the worst single step is the amortised argument from chapter 2.
  4. What signals that a problem wants a monotonic stack?
    Phrasing of the form "for each element, find the nearest element to its left or right that is greater or smaller" — next greater element, daily temperatures, stock span, largest rectangle in a histogram, trapping rain water. The naive solution scans outward from each element and is O(n²); the stack maintains exactly the candidates that could still be an answer, so each is resolved once.
  5. You need a stack and a queue in the same algorithm. What do you reach for?
    A deque for both, or a list for the stack and a deque for the queue. A deque supports O(1) operations at both ends, so it can act as either. In Python a plain list is a perfectly good stack — append and pop are both O(1) at the end — and it has better constants than a deque, so use a list for stacks and a deque wherever the front is involved.
