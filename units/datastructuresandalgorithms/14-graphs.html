Graphs and traversal

The most broadly applicable structure in the unit, because almost anything with relationships is a graph: road networks, dependencies, social connections, state machines, file systems, web pages. Two traversal algorithms cover most of what you will ever need, and the difference between them is one data structure.

The two traversals

One algorithm, two data structures

BFS and DFS are the same loop — take a vertex from a container, mark it, add its unvisited neighbours. A queue makes it breadth-first: the oldest vertex comes out next, so exploration spreads level by level. A stack makes it depth-first: the newest comes out next, so it plunges down one path before backtracking. Swap the container and you swap the algorithm.

Breadth first against depth first
Same graph, same start, one container different
python
from collections import deque

def bfs(g, start):
    seen = {start}                      # mark when ENQUEUED, not when dequeued —
    q = deque([start])                  # otherwise a vertex can enter the queue twice
    order, dist = [], {start: 0}
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            if v not in seen:
                seen.add(v)
                dist[v] = dist[u] + 1   # shortest path in an UNWEIGHTED graph
                q.append(v)
    return order, dist                  # O(V + E)

def dfs(g, u, seen=None):
    if seen is None: seen = set()
    seen.add(u)
    for v in g[u]:
        if v not in seen:
            dfs(g, v, seen)
    return seen                        # O(V + E), O(V) stack depth

def dfs_iterative(g, start):          # when the graph might be deep
    seen, stack, order = set(), [start], []
    while stack:
        u = stack.pop()
        if u in seen: continue          # here we mark on POP, so duplicates are possible
        seen.add(u); order.append(u)
        for v in reversed(g[u]):        # reversed to match the recursive order
            if v not in seen: stack.append(v)
    return order

Three graph-traversal bugs
  1. No visited set. Any cycle makes the traversal run forever. The tree algorithms in chapter 10 needed no such set because trees have no cycles — graphs do.
  2. Marking on dequeue rather than enqueue in BFS. A vertex can then be added to the queue several times before it is first processed, which does not break correctness but can blow the queue up to O(E).
  3. Using list.pop(0) as a queue. Chapter 5's O(n) trap, and BFS is where it bites hardest — it turns an O(V + E) algorithm into O(V² + VE).

# UNDIRECTED: a visited neighbour is a cycle — unless it is where you came from
def has_cycle_undirected(g, u, parent, seen):
    seen.add(u)
    for v in g[u]:
        if v not in seen:
            if has_cycle_undirected(g, v, u, seen): return True
        elif v != parent:                 # ← the whole difference
            return True
    return False

# DIRECTED: you need three states, not two
WHITE, GREY, BLACK = 0, 1, 2          # unvisited / in progress / finished
def has_cycle_directed(g, u, colour):
    colour[u] = GREY
    for v in g[u]:
        if colour[v] == GREY: return True   # a back edge to something still on the stack
        if colour[v] == WHITE and has_cycle_directed(g, v, colour): return True
    colour[u] = BLACK                     # finished — reaching it again is fine
    return False

# reaching a BLACK vertex is NOT a cycle: a diamond A→B→D, A→C→D has none

Topological sort

Order the vertices of a DAG so that every edge points forwards. Build systems, task schedulers, spreadsheet recalculation, course prerequisites and package managers all reduce to this.

Kahn's algorithm
Repeatedly take anything with nothing left to wait for
python
def topo_sort(g, vertices):
    indeg = {v: 0 for v in vertices}
    for u in g:
        for v in g[u]: indeg[v] += 1

    q = deque(v for v in vertices if indeg[v] == 0)   # nothing depends on these
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1                # u is done, so v waits for one fewer
            if indeg[v] == 0:
                q.append(v)

    if len(order) != len(vertices):
        raise ValueError("cycle detected")   # ← a free cycle check
    return order                          # O(V + E)

# swap the deque for a heap and you get the lexicographically smallest
# valid order — useful when the output must be deterministic

Implicit graphs

A great many problems are graphs without ever building one. A grid is a graph where each cell's neighbours are the four adjacent cells; a puzzle is a graph where each state's neighbours are the states one move away; a word ladder is a graph where two words are adjacent if they differ by one letter. In all of them you write BFS or DFS exactly as above and generate neighbours on demand instead of looking them up. Recognising that a problem is a graph traversal is usually the hard part — the code afterwards is the standard template.

Self-check

  1. What is the only structural difference between BFS and DFS?
    The container holding vertices waiting to be explored. A queue yields the oldest first, so exploration spreads outward level by level. A stack yields the newest first, so it plunges along one path and backtracks. Everything else — the visited set, the neighbour loop, the O(V + E) bound — is identical. Recursive DFS uses the call stack as its container, which is why it is the natural depth-first form.
  2. Why does BFS give shortest paths in an unweighted graph but not a weighted one?
    Because BFS explores in order of edge count, so the first time it reaches a vertex it has used the fewest possible edges. With weights, fewest edges is not cheapest — one long edge can beat three short ones — so the first arrival is no longer optimal. Dijkstra fixes this by exploring in order of accumulated cost using a priority queue, which is chapter 15.
  3. Why does directed cycle detection need three colours when undirected needs two?
    Because in a directed graph, reaching an already-visited vertex is only a cycle if that vertex is still on the current recursion path. A diamond — A→B→D and A→C→D — reaches D twice with no cycle at all. Grey means "in progress, on the stack" and finding a grey vertex is a genuine back edge; black means "finished" and is harmless. In an undirected graph the ambiguity is different: every edge can be traversed back, so the check is just "visited and not my parent".
  4. How does topological sort detect a cycle for free?
    By counting. Kahn's algorithm only emits a vertex once its in-degree reaches zero, and vertices inside a cycle mutually depend on each other, so none of their in-degrees ever drops to zero. If the output is shorter than the vertex count, the missing vertices are exactly those in or downstream of a cycle. That is why build systems report circular dependencies as a natural by-product of computing build order.
  5. A million users with a hundred friends each. Adjacency list or matrix?
    List, decisively. The matrix is 10¹² cells of which 99.99% are zero — around a terabyte even at one bit per cell. The list holds 10⁸ entries and iterating a user's friends is O(100) rather than O(10⁶). A matrix earns its place only on dense graphs, or when you need constant-time "is there an edge between u and v" on a graph small enough for V² to be affordable.
  6. You need the shortest sequence of moves to solve a puzzle. What is the graph?
    The vertices are puzzle states and the edges are legal moves — an implicit graph you never build. BFS from the start state finds the fewest-move solution, generating each state's neighbours on demand and keeping a visited set of states already seen. The practical constraints are memory, since BFS holds an entire frontier, and hashing states so the visited set works. Bidirectional search from both start and goal is the standard optimisation when the state space is large.
