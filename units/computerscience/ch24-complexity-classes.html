Complexity classes

Checking that a set of twenty numbers sums to a target takes a handful of additions. Finding which set, or proving that none does, took 20,971,520 operations on the same input. Both facts are about the same problem, and the gap between them is the most important open question in the subject.

P: what "efficient" is taken to mean

P is the set of decision problems solvable in time polynomial in the input length — n, n², n³ and so on. Sorting, shortest paths, matching, linear programming and primality testing are all in P.

The definition is a deliberate simplification, and two objections to it are correct. An n¹⁰⁰ algorithm is useless in practice; a 2n/1000 algorithm is fine for realistic n. But the class is chosen because it is robust: it does not change if you switch from a Turing machine to a RAM model or from one reasonable programming language to another, and it is closed under composition — a polynomial number of calls to a polynomial subroutine is still polynomial. No other natural threshold has those properties.

Input length, not input value

This distinction causes more confusion than anything else in the chapter. A number W written in binary has input length about log₂ W, so an algorithm running in Θ(W) time is exponential in the input length. Chapter 22's knapsack DP is Θ(n·W) and knapsack is NP-hard; the two facts are compatible because W is a value. Algorithms like that are pseudo-polynomial, and they are genuinely useful when the numbers are small and useless when they are not.

NP: easy to check, apparently hard to find

NP is the set of decision problems whose yes answers have a certificate that can be verified in polynomial time. The name is "nondeterministic polynomial", not "non-polynomial" — a common and consequential misreading.

On twenty numbers with a target of 100, the search finds an answer early and stops after 4,480 operations, and verifying that answer takes five additions. Change the target to 1 — which no subset can reach — and the search must rule out every possibility: 20,971,520 operations, the full 2²⁰ masks times twenty additions each.

NP is asymmetric on purpose

A yes answer has a short certificate: here are the five numbers, add them up. A no answer has no obvious certificate at all — "no subset works" cannot be demonstrated without, apparently, checking them all. That asymmetry is the definition. The mirror class co-NP contains problems whose no answers are cheaply verifiable, and whether NP = co-NP is another open question. A problem in both is a strong hint that it is in P: primality was known to be in NP ∩ co-NP for decades before AKS proved it is in P in 2002.

P ⊆ NP trivially: if you can find the answer in polynomial time you can verify one too, by ignoring the certificate and solving it yourself. Whether the containment is strict is the P versus NP question.

Reductions, and what NP-complete means

A reduction from problem A to problem B is a polynomial-time transformation of any instance of A into an instance of B with the same answer. If such a thing exists, B is at least as hard as A — solve B efficiently and you have solved A efficiently too.

NP-hard
At least as hard as everything in NP: every NP problem reduces to it. An NP-hard problem need not be in NP, and need not even be a decision problem — the halting problem is NP-hard.
NP-complete
In NP and NP-hard. These are the hardest problems that still have cheap certificates, and they stand or fall together: a polynomial algorithm for any one of them gives a polynomial algorithm for all of them.

The Cook-Levin theorem (1971) provided the first NP-complete problem by showing that any nondeterministic polynomial computation can be encoded as a boolean formula: SAT is NP-complete. Everything since has been a chain of reductions from there — Karp's 1972 paper gave 21 more in one go, and thousands are now known.

Every pair differs by what looks like a trivial change — two literals instead of three, edges instead of vertices, splittable instead of atomic — and lands on opposite sides of the divide. There is no reliable intuition for which side a problem falls on, which is exactly why the catalogue is worth knowing.

P versus NP

Is every problem whose solution can be checked quickly also solvable quickly?

Open since 1971, one of the seven Millennium Prize Problems, and almost universally believed to be answered no. A 2019 poll of complexity theorists found 88% expecting P ≠ NP.

If P = NP

Most public-key cryptography collapses, since it rests on problems being hard to invert. But it would also mean automated theorem proving, protein folding, optimal scheduling and much of machine learning become tractable. The constructive proof would matter as much as the result — an n¹⁰⁰ algorithm would settle the question and change nothing practical.

If P ≠ NP

The status quo is confirmed, and thousands of problems are permanently out of reach of exact efficient solution. This is what everyone already assumes and builds around, which is why the proof would be a mathematical landmark rather than an engineering event.

Why it is so hard to settle

Three barrier results explain the lack of progress, and each rules out a whole family of proof techniques. Relativisation (Baker-Gill-Solovay, 1975): there are oracles under which P = NP and others under which P ≠ NP, so any argument that survives adding an oracle cannot decide it. Natural proofs (Razborov-Rudich, 1994): a broad class of circuit lower-bound arguments would, if they worked, break cryptographic pseudorandom generators. Algebrisation (Aaronson-Wigderson, 2008) closes the main loophole in the first. Whatever the proof looks like, it will not look like anything currently known.

Living with hardness

"NP-complete" is a statement about worst-case exact solutions to arbitrary instances. Real problems are rarely arbitrary, and you rarely need exact.

On ten cities, exhaustive search examines 9! = 362,880 tours to find the optimum of 251.6. Nearest neighbour does 90 operations and returns 296.1 — 17.7% worse, for a 4,032-fold saving. Running 2-opt on that tour improves it to 287.4, or 14.2% above optimal.

Scaling is what makes this necessary rather than merely convenient. Twenty cities is 1.22 × 10¹⁷ tours: at a billion per second, 3.9 years. Twenty-five cities is 6.2 × 10²³ tours, or 19.7 million years. Held-Karp's dynamic programming reduces n! to 2n·n², which at n = 25 is 2.1 × 10¹⁰ instead of 6.2 × 10²³ — an enormous improvement that is still exponential and still runs out at around 30 cities.

The lower bound trick

You can often prove a heuristic answer is good without ever computing the optimum. A TSP tour minus one edge is a spanning tree, so the MST weight is a lower bound on the optimal tour. On the ten-city instance the MST weighs 200.2, so 2-opt's tour of 287.4 is provably within 44% of optimal — and the true gap turns out to be 14%. The bound is loose, but it is free, it requires no knowledge of the answer, and it is the difference between "the heuristic seems fine" and a statement you can defend.

The practical upshot: SAT solvers, integer programming solvers and constraint solvers routinely dispatch instances with millions of variables. Worst-case hardness says nothing about your instance, and the correct response to discovering your problem is NP-complete is to stop looking for a polynomial algorithm and start looking for a solver — not to give up.

UndecidableNo algorithm exists at allThe halting problem, program equivalence, Rice's theorem

Undecidability is a categorically stronger statement than NP-hardness, and worth keeping distinct. NP-hard means no efficient algorithm is known; undecidable means no algorithm exists, at any cost, ever. Turing proved in 1936 that no program can decide whether an arbitrary program halts, and Rice's theorem generalises it savagely: every non-trivial semantic property of programs is undecidable.

That is why static analysers, type checkers and linters are all necessarily either incomplete, unsound, or both — they must reject some correct programs, accept some incorrect ones, or fail to terminate. It is a theorem about the limits of tooling, not a criticism of any particular tool.

Check yourself

What does the N in NP stand for?

Nondeterministic polynomial, not "non-polynomial". NP is the set of problems a nondeterministic machine could solve in polynomial time by guessing a certificate and checking it — equivalently, the set whose yes answers have polynomial-time verifiable certificates. P ⊆ NP, so every efficiently solvable problem is in NP; reading the N as "not polynomial" makes that containment look contradictory, which is how the misreading gets noticed.

Why is subset sum easy to verify and hard to solve?

A yes answer comes with a certificate — here are the five numbers — and checking it is five additions. Finding it means searching 2n subsets. The measured asymmetry on twenty numbers: with a target of 100 the search stops early after 4,480 operations, but with a target of 1, which is unreachable, it must rule out every possibility — 20,971,520 operations against five to verify. Note where the real cost is: proving no. NP guarantees a cheap certificate only for yes.

Knapsack has a Θ(n·W) algorithm and is NP-hard. How?

Because W is a numeric value, not an input length. A capacity is written in about log₂ W bits, so Θ(W) is exponential in the size of its encoding. The demo shows the same effect on subset sum: the DP handles a target of 100 in 1,650 operations and a target of 6,000,007 in over twelve million — for only three items. Such algorithms are pseudo-polynomial: genuinely useful when the numbers are small, useless when they are large, and no evidence at all about P versus NP.

You want to prove your new problem X is NP-hard. Which way does the reduction go?

From a known NP-hard problem to X. You must show that any instance of, say, 3-SAT can be transformed in polynomial time into an instance of X with the same answer — so a fast algorithm for X would give a fast algorithm for 3-SAT. Reducing X to 3-SAT proves the opposite: that X is no harder than 3-SAT, which is how you show something is easy. The direction is what everyone gets backwards, and the mnemonic is that you transform the problem you are studying into the one you already understand.

2-SAT is linear time and 3-SAT is NP-complete. What should you take from that?

That there is no reliable intuition for which side of the divide a problem falls on. The same pattern recurs: shortest path is polynomial and longest path is NP-complete; Eulerian cycle is linear and Hamiltonian cycle is NP-complete; 2-colouring is a BFS and 3-colouring is NP-complete; fractional knapsack is greedy and 0/1 knapsack is NP-hard. Each pair differs by what looks like a trivial change. The practical consequence is to check the catalogue rather than trusting a feeling about difficulty.

Your scheduling problem turns out to be NP-complete. What do you actually do?

Stop looking for a polynomial algorithm and start choosing among five options: an approximation with a proven ratio; a heuristic with no guarantee but good behaviour; an exponential algorithm that is smart enough in practice, such as a SAT or ILP solver, which routinely handle millions of variables; a restriction to the special case you actually have; or a parameterised algorithm if some parameter is small. On ten cities, nearest neighbour was 17.7% worse than optimal for 1/4,032 of the work. NP-completeness is a statement about worst-case exact solutions to arbitrary instances, and yours is probably neither worst-case nor arbitrary.

How can you tell a heuristic tour is good without computing the optimum?

Compute a lower bound. Removing any one edge from a TSP tour leaves a spanning tree, so the minimum spanning tree's weight can never exceed the optimal tour — it is a free lower bound from a polynomial algorithm. On the ten-city instance the MST weighs 200.2 and 2-opt's tour is 287.4, so the tour is provably within 44% of optimal; the true gap is 14%, so the bound is loose but honest. Lower bounds are also what makes branch and bound work, since a partial solution already worse than the best known can be abandoned unexplored.

Ten things to carry forward

  1. P is polynomial in the input length, and the class is chosen for robustness rather than realism.
  2. Θ(n·W) is pseudo-polynomial when W is a value: three items and a large target cost twelve million operations.
  3. NP means nondeterministic polynomial, not non-polynomial, and P ⊆ NP.
  4. NP guarantees cheap certificates for yes only. Proving no took 20,971,520 operations against five to verify.
  5. Reductions go from the known-hard problem to yours, and that direction is the part people invert.
  6. NP-complete problems stand or fall together — one polynomial algorithm settles all of them.
  7. Nearly identical problems land on opposite sides: 2-SAT versus 3-SAT, Eulerian versus Hamiltonian, shortest versus longest path.
  8. Factorial growth is not survivable. Twenty cities is 3.9 years of brute force; twenty-five is 19.7 million.
  9. Heuristics get most of the answer for almost none of the cost — 17.7% worse for 1/4,032 of the work.
  10. Undecidable is categorically worse than NP-hard, and Rice's theorem is why every static analyser is incomplete, unsound, or both.
