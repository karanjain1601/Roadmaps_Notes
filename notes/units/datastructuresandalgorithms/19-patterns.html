Problem-solving patterns

Most problems that look novel are one of about a dozen shapes wearing a costume. This chapter is the shapes and — more usefully — the signals that identify them, because recognition is the skill that separates people who solve problems from people who have memorised solutions.

Two pointers

Instead of nested loops over every pair, walk two indices under a rule that guarantees neither ever needs to go back. O(n²) becomes O(n).

# opposite ends — why it is correct: at each step one pointer's best
# partner is exhausted, so moving it can never skip the answer
def two_sum_sorted(a, target):
    i, j = 0, len(a) - 1
    while i < j:
        s = a[i] + a[j]
        if s == target: return i, j
        if s < target:  i += 1      # need bigger; a[i] is the smallest left
        else:           j -= 1      # need smaller

# same direction — read and write pointers
def dedupe_sorted(a):
    w = 1
    for r in range(1, len(a)):
        if a[r] != a[w-1]:
            a[w] = a[r]; w += 1
    return w                        # O(n), O(1) space, order preserved

Sliding window

Two pointers where the space between them is the answer. The right edge always advances; the left edge advances only when the window becomes invalid — so both traverse the array once and the whole thing is O(n).

# ── fixed size k ──
def max_sum_k(a, k):
    s = sum(a[:k]); best = s
    for i in range(k, len(a)):
        s += a[i] - a[i-k]          # add one, drop one — O(1) per step
        best = max(best, s)
    return best

# ── variable size: grow right, shrink left while invalid ──
def longest_unique(s):
    seen, left, best = {}, 0, 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1     # jump past the previous occurrence
        seen[ch] = right
        best = max(best, right - left + 1)
    return best                     # O(n): each index is entered and left once

python — fast and slow pointers
# signal: a cycle, a middle, or a duplicate in a value-indexed array
def find_duplicate(nums):        # n+1 numbers in 1..n, one repeated
    slow = fast = nums[0]        # treat the array as a linked list:
    while True:                   # i → nums[i]. A duplicate makes a cycle
        slow, fast = nums[slow], nums[nums[fast]]
        if slow == fast: break
    slow = nums[0]
    while slow != fast:
        slow, fast = nums[slow], nums[fast]
    return slow                   # chapter 4's Floyd, on an array
python — merge intervals
# signal: intervals, meetings, ranges, overlaps. Sorting first is the move.
def merge(intervals):
    intervals.sort()                       # by start — this is the whole trick
    out = []
    for s, e in intervals:
        if out and s <= out[-1][1]:
            out[-1][1] = max(out[-1][1], e)   # overlaps — extend
        else:
            out.append([s, e])
    return out                             # O(n log n), dominated by the sort

python — cyclic sort
# signal: the array contains 1..n, or 0..n−1, and you need the missing
# or duplicated one in O(1) space
def cyclic_sort(a):
    i = 0
    while i < len(a):
        j = a[i] - 1                     # where a[i] belongs
        if a[i] != a[j]: a[i], a[j] = a[j], a[i]
        else:            i += 1
    return a
    # each swap puts one value home permanently, so it is O(n)
    # afterwards, any index where a[i] != i+1 identifies the anomaly

Backtracking

Build a solution incrementally, abandon a branch the moment it cannot succeed, and undo the last choice on the way out. Pruning is where the speed comes from — without it this is brute force with extra steps.

Six queens
Rejections happen early, which is the entire point
python — the template, and the pruning that matters
def solve_n_queens(n):
    cols, diag, anti = set(), set(), set()
    board, out = [], []

    def place(r):
        if r == n:
            out.append(board[:]); return
        for c in range(n):
            if c in cols or r-c in diag or r+c in anti:
                continue                       # ← prune: O(1) rejection
            cols.add(c); diag.add(r-c); anti.add(r+c); board.append(c)
            place(r + 1)                       # explore
            cols.remove(c); diag.remove(r-c); anti.remove(r+c); board.pop()
        #                                       ↑ undo — the defining move
    place(0)
    return out

# r−c is constant along a ↘ diagonal; r+c along a ↗ one. Those two
# identities turn "is this square attacked?" from O(n) into O(1).

Greedy, and when it is allowed

Take the locally best option and never reconsider. When it works it is simpler and faster than dynamic programming; when it does not, it produces a confidently wrong answer.

The exchange argument

To justify a greedy rule, show that any optimal solution can be transformed into the greedy one without getting worse. For interval scheduling: take the meeting that ends earliest. If some optimal schedule starts with a different meeting, swapping in the earliest-ending one leaves at least as much room for everything after it, so the result is still optimal. That is a proof, and it is the standard shape. If you cannot construct such an argument, be suspicious — coin change with arbitrary denominations is the classic case where greedy looks obvious and is wrong: with coins 1, 3, 4 and a target of 6, greedy takes 4+1+1 while the optimum is 3+3.

Reading the constraints

The input bounds usually name the intended complexity, and therefore the pattern. n ≤ 10 means permutations are fine — backtracking. n ≤ 20 suggests subsets or bitmask DP. n ≤ 500 permits O(n³), which often means Floyd-Warshall or interval DP. n ≤ 5,000 permits O(n²) — many DP tables. n ≤ 10⁶ demands O(n) or O(n log n), so a window, a sort, a heap, or a single pass. Read that number before you start thinking.

Self-check

  1. Why is a sliding window O(n) when both pointers move inside a loop?
    Because neither pointer ever moves backwards, so each index is entered by the right pointer once and left by the left pointer once — at most 2n pointer movements in total across the whole run. A single outer iteration might advance the left pointer many times, but that work was paid for by the right pointer's earlier advances. This is the same amortised argument as the monotonic stack in chapter 5.
  2. When does the sliding window fail on a subarray-sum problem?
    When the array contains negative numbers. The window relies on monotonicity — extending the window increases the sum and shrinking it decreases the sum — so that shrinking is guaranteed to fix an invalid window. Negatives break that, since extending can lower the sum. For "subarray sums to exactly k" with negatives, use prefix sums with a hash map of previously seen prefix values instead.
  3. What makes backtracking different from brute force?
    Pruning. Both explore a tree of choices, but backtracking abandons a branch as soon as it can prove no completion works, cutting off the entire subtree beneath it. In six queens, a naive enumeration examines 6⁶ = 46,656 placements; the pruned search visits a few hundred nodes. The other defining feature is the undo step, which lets one mutable state be reused across the whole search instead of copying it at every node.
  4. How do you justify a greedy algorithm?
    With an exchange argument: show that any optimal solution can be transformed step by step into the greedy one without becoming worse, so the greedy result is also optimal. For interval scheduling, swapping in the earliest-ending meeting leaves at least as much room for the rest. If you cannot construct such an argument, assume greedy is wrong until proven otherwise — the coin system 1, 3, 4 with target 6 is the standard counterexample.
  5. The input says n ≤ 20 and asks for an optimal selection. What does that suggest?
    Subsets, so 2²⁰ ≈ one million states — bitmask enumeration or bitmask dynamic programming. That bound is chosen deliberately: it is too large for permutations (20! is astronomical) and small enough that iterating every subset is trivial. Constraints are a hint about the intended solution, and reading them before thinking about the algorithm is one of the cheapest habits available.
  6. An array holds the numbers 1 to n with one missing and one duplicated, and you may use O(1) space. What pattern?
    Cyclic sort. Because the values are exactly the index range, each value has a home position, and repeatedly swapping values home takes O(n) — each swap places one value permanently. Afterwards, the single index where a[i] ≠ i+1 reveals both the duplicate sitting there and the missing value it displaced. Fast-and-slow pointers on the value-as-pointer graph is the alternative when the array must not be modified.
