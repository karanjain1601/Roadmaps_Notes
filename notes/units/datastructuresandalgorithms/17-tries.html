Tries and strings

A hash table can tell you whether "car" is a word. It cannot tell you which words begin with "car" without scanning everything. A trie answers both, because it stores the prefix structure of the data rather than destroying it.

The prefix tree

Each edge is a character; each path from the root spells a prefix; nodes carrying a flag mark where a complete word ends. Words sharing a prefix share the path that spells it.

Autocomplete
Type a prefix — the descent is the query
python
class TrieNode:
    __slots__ = ("children", "is_word")
    def __init__(self):
        self.children = {}          # character → TrieNode
        self.is_word = False

class Trie:
    def __init__(self): self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True          # O(m) — independent of how many words exist

    def _walk(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children: return None
            node = node.children[ch]
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_word

    def starts_with(self, prefix):
        return self._walk(prefix) is not None     # the operation a hash table cannot do

    def completions(self, prefix):
        node = self._walk(prefix)
        out = []
        def collect(n, acc):
            if n.is_word: out.append(prefix + acc)
            for ch, child in sorted(n.children.items()):
                collect(child, acc + ch)
        if node: collect(node, "")
        return out                  # O(prefix + size of the subtree)

The property that makes it worth the memory

Lookup cost depends on the length of the key, not on the number of keys stored. A trie holding ten words and one holding ten million answer a five-character query in the same five steps. Hash tables share that property for exact lookup but throw away the prefix structure; a sorted array keeps the structure but pays a log n factor and cannot insert cheaply.

The memory problem, and the fixes

A naive trie allocates a node for every character position, and if each node holds a 26-entry array most of it is empty. Storing a million English words can cost far more than the words themselves.

  • Hash map per node instead of a fixed array — pay a little speed for a lot of space. This is what the code above does.
  • Compressed trie (radix tree, PATRICIA): collapse any chain of single-child nodes into one edge labelled with the whole substring. Dramatically fewer nodes on sparse data, and what IP routing tables use.
  • Ternary search trie: each node has one character and three children — smaller, less to allocate, log-factor slower.
  • DAWG: merge identical suffixes so the trie becomes a directed acyclic graph. Very compact for a fixed dictionary; awkward to update.

String matching

Find a pattern of length m inside a text of length n. The obvious algorithm is O(nm), and the classic improvement is to notice that a mismatch tells you something you already knew.

Knuth-Morris-Pratt
On a mismatch, the pattern slides — the text pointer never moves back
python
def build_lps(p):
    """lps[i] = length of the longest proper prefix of p[:i+1]
       that is also a suffix of it."""
    lps = [0] * len(p)
    k = 0
    for i in range(1, len(p)):
        while k and p[i] != p[k]:
            k = lps[k-1]                # fall back to a shorter candidate
        if p[i] == p[k]: k += 1
        lps[i] = k
    return lps

def kmp(text, p):
    lps, out, k = build_lps(p), [], 0
    for i, ch in enumerate(text):     # i NEVER goes backwards — that is the point
        while k and ch != p[k]:
            k = lps[k-1]                # slide the pattern, keep the overlap
        if ch == p[k]: k += 1
        if k == len(p):
            out.append(i - k + 1)
            k = lps[k-1]                # continue, allowing overlapping matches
    return out                        # O(n + m)
What the failure table encodes

Suppose the pattern ABABC matches four characters and then fails. Those four characters were ABAB — you already know the text ends with AB, which is also how the pattern starts. So instead of restarting from the next text position, slide the pattern forward by two and resume comparing from index 2. The failure table precomputes, for every prefix length, how far you may slide without missing a possible match. That is why the text pointer never has to move backwards, and why the whole scan is linear.

python — the rolling hash, which is worth knowing on its own
def rabin_karp(text, p, base=256, mod=10**9+7):
    n, m = len(text), len(p)
    if m > n: return []
    high = pow(base, m-1, mod)
    hp = ht = 0
    for i in range(m):                          # hash the pattern and the first window
        hp = (hp*base + ord(p[i])) % mod
        ht = (ht*base + ord(text[i])) % mod

    out = []
    for i in range(n - m + 1):
        if hp == ht and text[i:i+m] == p:      # verify — hashes can collide
            out.append(i)
        if i < n - m:                          # roll: drop one char, add the next
            ht = ((ht - ord(text[i])*high) * base + ord(text[i+m])) % mod
    return out

Self-check

  1. Why can a hash set not answer "which words start with car?"
    Because hashing deliberately destroys the relationship between similar keys — "car" and "card" land in unrelated buckets by design, since spreading similar inputs apart is what a good hash function does. There is no way to enumerate keys sharing a prefix without examining all of them, so the query is O(n·m). A trie keeps the prefix structure in the shape of the data, so the query is a walk of length p followed by a traversal of just the relevant subtree.
  2. What determines a trie lookup's cost?
    The length of the key, not the number of keys stored. A five-character search takes five steps whether the trie holds ten words or ten million. That is the property that makes tries attractive for dictionaries and routing tables, and it is bought with memory — a node per character position, which is the trade-off compressed variants exist to soften.
  3. What does the KMP failure table actually store?
    For each prefix of the pattern, the length of the longest proper prefix of it that is also a suffix of it. When a mismatch occurs after matching k characters, that value tells you how much of what you just matched is still usable as the start of a fresh attempt — so you slide the pattern forward and resume from that offset rather than restarting. It is precomputed in O(m) by matching the pattern against itself.
  4. Why is Rabin-Karp only "expected" O(n + m)?
    Because hashes can collide. Equal hashes mean the strings are probably equal, so every hash match must be verified with a real comparison at O(m). With a good hash and a large modulus collisions are rare and the expected cost is linear, but a crafted input — or bad luck — can force verification at every position, giving O(n·m). Its real strength is multi-pattern search and rolling windows rather than raw single-pattern speed.
  5. You need to find any of 5,000 banned phrases in a stream of text. What do you use?
    Aho-Corasick. Running KMP 5,000 times is O(5000·n); Aho-Corasick builds a single trie of all the patterns, adds failure links so a mismatch jumps to the longest usable suffix, and finds every occurrence of every pattern in one pass — O(n + total matches) after O(total pattern length) preprocessing. It is essentially KMP generalised to a trie, and it is what intrusion detection and content filters use.
  6. When is a compressed trie worth the complexity?
    When the data is sparse, so the trie is full of long chains of single-child nodes — URLs, file paths, IP prefixes, long identifiers with few shared branches. Collapsing each chain into one edge labelled with the whole substring can reduce the node count by an order of magnitude, and lookups get faster because there are fewer pointers to follow. On dense data such as a natural-language dictionary, where branching is frequent, there is much less to collapse and a plain trie is simpler.
