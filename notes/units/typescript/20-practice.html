Compiler errors, decoded

Read a long assignability error bottom-up: the last line is usually the real mismatch and everything above it is the path the checker took to get there.

CodeSaysMeans
TS2322Type 'X' is not assignable to type 'Y'The workhorse. Read it bottom-up: the last line of the error is usually the actual mismatch, and everything above it is the path to it. If both types look identical, suspect a nominal difference — a private field or a brand — or an exactOptionalPropertyTypes undefined.
TS2345Argument of type 'X' is not assignable to parameter of type 'Y'The same check at a call site. When 'Y' is never, this is almost always the exhaustiveness helper telling you a union grew — chapter 14.
TS2339Property 'x' does not exist on type 'Y'Either a typo, or the value has not been narrowed yet. On a union, it means the property is not on every member. On a library type, it may be a genuinely missing declaration — chapter 16.
TS2532 / TS18048Object is possibly 'undefined' / 'x' is possibly 'undefined'strictNullChecks doing its job. From an index access it is noUncheckedIndexedAccess, and the honest fix is a check rather than a !.
TS2531 / TS18047Object is possibly 'null' / 'x' is possibly 'null'Same, for null. Common on DOM queries, which return Element | null truthfully.
TS7006Parameter 'x' implicitly has an 'any' typenoImplicitAny. The compiler could not contextually type the parameter — usually a callback passed somewhere untyped, or a function assigned to a variable with no annotation.
TS7016Could not find a declaration file for module 'x'An untyped dependency. Try @types/x, then a small declare module. Chapter 16 — and this error is the flag earning its keep, because without it the module would silently be any.
TS2307Cannot find module 'x' or its corresponding type declarationsResolution, not typing. Check moduleResolution against the specifier's shape, whether the package publishes that subpath in exports, and whether a relative import needs a .js extension.
TS2835Relative import paths need explicit file extensionsnodenext. Write ./util.js even though the file is ./util.ts — chapter 10, and it is correct.
TS5097An import path can only end with '.ts' when allowImportingTsExtensions is enabledYou wrote the real filename. The flag exists but only alongside noEmit, because a .ts specifier in shipped JavaScript is a broken import.
TS2589Type instantiation is excessively deep and possibly infiniteA recursive conditional or mapped type nesting rather than iterating. Move the recursion to tail position with an accumulator, or cap the depth — chapters 8 and 19.
TS2590Expression produces a union type that is too complex to representA combinatorial explosion, usually from distributing a conditional over several large unions at once. Break it into named intermediate steps.
TS2564Property 'x' has no initializer and is not definitely assigned in the constructorstrictPropertyInitialization. If a framework assigns it, use declare x: T rather than x!: T — chapter 12.
TS2367This comparison appears to be unintentional because the types have no overlapUsually true and occasionally the sign of an over-narrow type. If the comparison is genuinely possible at runtime, the type is wrong — often a value that came from outside and was asserted.
TS2678Type 'x' is not comparable to type 'y'A case label that is not a member of the union being switched on. A typo, or a member that was removed.
TS2739 / TS2741Type 'X' is missing the following properties…An incomplete object. On a Record<Union, V> this is the exhaustiveness check firing — chapter 14.
TS2353 / TS2559Object literal may only specify known propertiesExcess property checking, which applies to fresh literals only. If assigning through a variable silences it, that is the freshness rule and not a fix — chapter 4.
TS1360 / TS2559Type does not satisfy the expected typeA satisfies failure. The value does not match the constraint; the inferred type is still whatever you wrote, so the report is about the check, not the value.
TS4082 / TS4023Default export of the module has or is using private nameDeclaration emit needs to write a type it cannot name — typically an inferred type referencing something not exported. Export the type, or annotate the export. isolatedDeclarations prevents the whole class.
TS2451Cannot redeclare block-scoped variable 'x'Two files declaring the same name at global scope, because neither is a module. Add export {} — chapter 10.

Glossary

ambient declaration
A declaration that describes something existing elsewhere, introduced with declare and emitting nothing.
any
A hole in the type system: all checks disabled, assignable to and from everything, and inherited by every derived value.
assertion function
A function whose return type is asserts x is T; narrows its argument for the rest of the scope, and the body is unverified.
assignability
Whether a value of one type may be used where another is expected. Structural, and the meaning of extends in a conditional type.
as const
Infers a value with literal types and readonly members rather than widening.
augmentation
Reopening a module's or the global scope's interfaces to add members, relying on declaration merging.
Awaited<T>
Recursively unwraps promise types; T for a non-promise.
bivariance
Accepting both covariant and contravariant assignment. Method-shorthand parameters are bivariant, which is deliberately unsound.
branded type
A nominal type simulated by intersecting a unique marker, so two structurally identical types stop being interchangeable.
bottom type
never — assignable to everything, nothing assignable to it.
checkJs
Type-checks .js files. Per-file opt-in is // @ts-check.
composite
A project configured for references; implies declaration and incremental.
conditional type
T extends U ? X : Y. Distributes per union member when the left side is a naked type parameter.
const type parameter
<const T>: infers the argument as though it had as const.
contravariance
Accepting a wider type in place of a narrower one. Correct for function parameters.
control-flow analysis
Narrowing a variable's type along each execution path from the checks the code performs.
covariance
Accepting a narrower type in place of a wider one. Correct for return types and readonly members.
declaration file
A .d.ts containing only types and declared values.
declaration merging
Two declarations of the same interface or namespace combining. Interfaces merge; type aliases do not.
discriminant
A literal-typed property whose value identifies which member of a union a value is.
discriminated union
A union whose members share a discriminant property, so narrowing and exhaustiveness work.
distribution
Evaluating a conditional type once per union member and unioning the results.
erasure
Types are removed before the code runs, so no type has any runtime effect. The unit's first principle.
exactOptionalPropertyTypes
Stops an optional property accepting an explicit undefined, so optionality means presence.
excess property check
Rejecting unknown properties on a fresh object literal. Assigning through a variable evades it.
exhaustiveness
A guarantee that every union member is handled, obtained by passing the narrowed value to a never parameter.
exports map
The package.json field declaring a package's entry points and, via a types condition, its declarations.
freshness
The property of an object literal that makes excess property checking apply to it.
generic
Parameterised over a type. Earns its keep only by relating two or more positions.
homomorphic mapped type
One written as [K in keyof T], which preserves the source's readonly and ? modifiers.
infer
Declares a type variable inside a conditional type's pattern, in scope in the true branch only.
imports map
The package.json field declaring private # aliases the runtime resolves itself.
indexed access
T[K] — the type of a property, distributing over a union of keys.
index signature
[k: string]: V — permits any key of that type, and claims a value exists for all of them.
isolatedDeclarations
Requires explicit types on exports so declarations can be emitted per file.
isolatedModules
Forbids constructs a per-file transpiler cannot compile correctly.
keyof
The union of an object type's keys.
literal type
A type inhabited by one value: "paid", 42, true.
mapped type
{ [K in Keys]: Value } — a loop over keys, with optional modifiers and an as clause.
module
The option deciding what module format is emitted.
moduleResolution
The option deciding how specifiers are resolved. Must be consistent with module.
narrowing
Refining a variable's type within a scope from a check the code performs.
never
The bottom type. The empty union, so distribution over it runs zero times.
NoInfer<T>
Marks a position as checked-against rather than contributing to inference.
nominal typing
Compatibility by declared name. TypeScript is structural; branding and #private simulate it.
noImplicitAny
Errors where the compiler would otherwise silently infer any. The highest-value flag.
noUncheckedIndexedAccess
Makes an index access return T | undefined, which is the truth.
Omit
Removes keys. Its key parameter is keyof any, so a typo silently removes nothing.
overload
Several call signatures for one implementation. Cannot handle a union argument; resolution picks the first match.
parameter property
constructor(private x: T) — emits an assignment, one of the four non-erasing features.
paths
A tsconfig alias mapping. tsc does not rewrite specifiers, so the runtime must be told separately.
Pick
Keeps keys. Constrained to keyof T, unlike Omit.
predicate
x is T as a return type; narrows the argument at the call site, with an unverified body.
Prettify
An identity mapped type that flattens an intersection for legible hovers.
project reference
A references entry letting tsc --build skip unchanged packages and read their declarations.
readonly
Blocks direct assignment. Shallow, erased, and lost through an alias.
Record<K, V>
A mapped type whose keys are exactly K; an exhaustiveness check when K is a union.
Result
A union of success and failure, putting expected failure in the signature. Needs a must-use rule.
satisfies
Checks a value against a type without replacing its inferred type.
skipLibCheck
Stops checking .d.ts files. A speed win that hides conflicts between dependencies.
strict
Eight flags in one. strictNullChecks is most of the value.
strictFunctionTypes
Enforces contravariant parameter checking — for function-typed properties, not method shorthand.
strictNullChecks
Removes null and undefined from every type unless stated. The flag that decides whether TypeScript is worth having.
structural typing
Compatibility by shape. Two unrelated types with the same members are the same type.
target
The syntax level emitted. Does not decide which built-ins exist — that is lib.
template literal type
A string type with interpolated type positions; infer can pattern-match inside one.
top type
unknown — everything assignable to it, and it permits nothing until narrowed.
ts-expect-error
Suppresses one error and fails if that line stops erroring. Always preferable to ts-ignore.
ts-ignore
Suppresses every error on the next line, forever, including ones added later.
type parameter
A named placeholder introduced by <T>.
typeof (type position)
The type of a value, which is how as const objects become types.
unknown
The honest any: accepts everything, permits nothing until narrowed.
useDefineForClassFields
Whether a field initialiser is an assignment or a defineProperty. Changes whether a base setter runs.
useUnknownInCatchVariables
Types a caught error unknown rather than any.
verbatimModuleSyntax
Emits imports exactly as written, so import type is required where a type-only import is meant.
variance
How a type's compatibility follows its parts'. Parameters contravariant, returns covariant, methods bivariant.
widening
Inferring a general type from a literal value. let s = "paid" is string.

Questions

Foundations 10

  1. Which two properties explain most of TypeScript's behaviour?
    Erasure — a type never checks data at runtime — and structural comparison, where two unrelated types with the same shape are the same type.
  2. Name the four features that do not erase.
    enum, parameter properties, decorators, and namespace. Everything else is deleted before the code runs.
  3. Why is const o = { status: "paid" } not { status: "paid" }?
    The binding is const but the object's property is mutable, so the property type widens to string. as const fixes it.
  4. What replaces an enum?
    An as const array or object plus typeof xs[number] — a union of literals that erases and is structural.
  5. What is never, in one sentence?
    The bottom type: nothing is assignable to it, it is assignable to everything, and it is the empty union.
  6. Why is any not a position in the lattice?
    Because it is assignable both to and from every type, which no consistent position allows. It is a hole, not a top or bottom.
  7. What does satisfies do that an annotation does not?
    Checks the value without replacing its inferred type, so literals and precise keys survive.
  8. Where is narrowing lost, and where is it unsoundly kept?
    Lost inside a nested function over a let; kept across a function call, which is unsound because the call could have reassigned.
  9. Why does a flags object have more impossible states than a union?
    Because n independent booleans give 2ⁿ combinations, most meaningless; a union has exactly as many states as you declared.
  10. What is the one thing a type predicate's body gets from the compiler?
    Nothing. The claim is unverified, which is why it belongs in one named, tested function.

Shapes and abstraction 16

  1. Which interface/type differences actually decide?
    Unions, primitives and tuples, and computed types need type; declaration merging for module augmentation needs interface.
  2. What are the four forms of optionality?
    k?: T, k: T | undefined, k?: T | undefined, and the key being absent. exactOptionalPropertyTypes separates them.
  3. Why does assigning through a variable evade excess property checking?
    Freshness. The check applies only to an object literal at the point of assignment; a variable's type has already been established.
  4. What is wrong with readonly as immutability?
    It is shallow, erased, and lost through an alias — a Readonly<T> is assignable to a mutable T.
  5. Why are method parameters bivariant?
    So Array<Dog> stays assignable to Array<Animal>. It is a deliberate unsoundness; function-typed properties are checked correctly.
  6. When do overloads fail?
    On a union argument — resolution must pick one signature for the whole thing. A generic with a conditional return distributes instead.
  7. What is the minimum bar for a type parameter?
    It must appear in at least two positions, so it relates them. One position in the return is an as the caller writes.
  8. What does a constraint give the implementation?
    Permission. An unconstrained T is unknown inside the body; T extends { id: string } lets you read .id.
  9. How do you remove a key in a mapped type?
    Remap it to never in the as clause. This is the whole filtering mechanism and has no built-in.
  10. Why is Omit less safe than Pick?
    Its key parameter is keyof any, so Omit<T, "typo"> compiles and removes nothing — dangerous on a DTO where the omission is doing security work.
  11. What does an as clause cost a mapped type?
    Homomorphism. The source's readonly and ? modifiers are no longer preserved.
  12. When does a conditional type distribute?
    When a naked type parameter is on the left of extends. Wrap either side — [T] extends [X] — and it does not.
  13. Why does distributing over never give never?
    never is the empty union, so the conditional runs zero times and the union of zero results is never.
  14. What does any do to a conditional type?
    Takes both branches and unions them, because the compiler cannot decide whether it matches.
  15. Why does tail position matter for recursion?
    The compiler iterates rather than nests: ~1,000 levels instead of ~50 before "excessively deep".
  16. How does the same infer variable in two positions combine?
    Unioned in covariant positions, intersected in contravariant ones — which is the UnionToIntersection trick.

Escape hatches 14

  1. Why is const n: number = anyValue the dangerous line?
    any is assignable to everything, so an unchecked value is laundered into a variable with a confident type nothing can distinguish from a real one.
  2. Order the escape hatches by cost.
    satisfies and as const give up nothing; a predicate, then as, then the double cast and !; then any, then @ts-expect-error, and @ts-ignore is worst.
  3. What rule does as follow?
    The types must overlap in one direction. as unknown as defeats it in four characters, so the real benefit is that it is greppable.
  4. Why @ts-expect-error over @ts-ignore?
    It fails when the line stops erroring, so a suppression cannot outlive the bug it worked around — and it does not hide new errors.
  5. Why does import "./util.js" resolve to util.ts?
    The specifier describes what the runtime will resolve, and the compiler does not rewrite it. So you write the output path.
  6. Where does TypeScript look for a package's types?
    exports types condition, top-level types/typings, a sibling .d.ts, @types/<name>, your own declare module — then any.
  7. Why is import type necessary rather than tidy?
    A single-file transpiler cannot know whether a name is a type, so without the marker it emits the import — creating a runtime dependency or a circular import.
  8. Why is paths insufficient on its own?
    tsc does not rewrite specifiers, so the bundler or runtime needs the same mapping. package.json imports is honoured directly.
  9. Which single flag matters most?
    strictNullChecks. Without it the compiler cannot report a single null dereference.
  10. Which three flags outside strict are worth adding?
    noUncheckedIndexedAccess, exactOptionalPropertyTypes, noImplicitOverride.
  11. What is the difference between target and lib?
    target is emitted syntax; lib is which built-ins the compiler believes exist. Choose lib from your support matrix.
  12. What does private actually guarantee?
    A compile-time check, and nominal incompatibility. Nothing at runtime — it is readable by index and appears in JSON.stringify.
  13. What does useDefineForClassFields change?
    Whether a field initialiser assigns or defines. With define semantics a subclass field shadows a base setter, so the setter never runs.
  14. Why can NestJS not move to standard decorators?
    Parameter decorators do not exist in the standard, and neither does emitDecoratorMetadata — the two things its injection model depends on.

In practice 24

  1. Why does a typed parameter guarantee nothing about incoming data?
    The type is erased and the check happened at call sites the compiler could see. Bytes from the network are not such a call site.
  2. What is the difference between validating and parsing?
    Validation returns a boolean and leaves you holding the same value; parsing returns a new value of a narrower type, so the type system carries the check.
  3. Which entry points are honest?
    process.env, localStorage.getItem, an imported JSON file, and your own function parameters. JSON.parse, res.json(), a generic client, DB rows, queue messages and worker messages are not.
  4. Why is api.get<Order>(url) worse than JSON.parse?
    It looks like the solution. The type argument appears only in the return, so nothing checks it, and every reader believes something was verified.
  5. Where does the parse go?
    On the first line of the entry point. Not the service layer, not the repository, and not twice.
  6. Why are database rows a boundary?
    The row type comes from your schema definition, not the database — so an unrun migration or a driver coercion passes silently.
  7. How does exhaustive(x: never) work?
    In the default branch every handled member has been narrowed away, so a complete switch leaves never, which is the only thing assignable.
  8. Why is exhaustiveness a refactoring property?
    When you write the switch you already know the cases. The value arrives when someone adds a variant and every site needing attention becomes a build error.
  9. Which call sites do not break when a union grows?
    A switch with a fallback default, an unannotated object literal, an if/else if chain, and a nested ternary.
  10. Why is a caught error unknown?
    JavaScript can throw anything. Narrow it, and re-throw what you do not recognise.
  11. When is Result worth it?
    For expected failures a caller must decide about. Not for bugs, which have no useful handling. And it needs a must-use lint rule or the return value gets discarded.
  12. What does await Promise.all([a, b]) give you?
    A tuple, so destructuring types each variable. A mapped array gives an array.
  13. Why is allSettled awkward?
    It resolves to an array of a discriminated union, so .value requires narrowing on status first.
  14. Why does forEach(async …) compile?
    forEach's callback returns void, which in a return position means the caller ignores it — so any return type is assignable, including a promise.
  15. What catches floating promises?
    A typed lint rule: no-floating-promises and no-misused-promises. The compiler catches one of eight common cases.
  16. Why does useEffect(async …) error when forEach does not?
    React types the slot as void | Destructor rather than bare void, so a promise is not assignable. A lesson for your own callbacks.
  17. Why declare only what you call from an untyped package?
    You can verify three functions; a complete declaration nobody checked is a large unverified surface whose size implies diligence that was not applied.
  18. What breaks module augmentation?
    A file with no top-level import or export — the declare module then replaces the package's types instead of extending them.
  19. Why is a wrong declaration worse than a missing one?
    A missing one gives an any that noImplicitAny reports. A wrong one gives a confident type over a false assumption, and no flag catches it.
  20. What does a wrapper module buy?
    It reduces the modules depending on untrusted types from however many use the library to one.
  21. Why start a migration with allowJs?
    It changes no source files and produces no errors, so the build stays green and the team keeps shipping.
  22. Why convert leaves before entry points?
    A converted file's types are only as good as its imports. A route handler over untyped services is annotated and unchecked.
  23. Which flag first in a migration, and which last?
    noImplicitAny first, because it makes the remaining work visible. strictNullChecks once the count is finite — it produces the largest spike and finds the real bugs.
  24. How do you enable a flag without going red?
    Insert @ts-expect-error with a ticket reference for each error, then ratchet the count down in CI.

Operating 12

  1. Why can esbuild not type-check?
    It transforms one file at a time and never builds a program. Type checking needs the whole graph — the same fact that makes it fast.
  2. What does isolatedModules forbid?
    Constructs whose output depends on another file: re-exporting a name without type, and const enum.
  3. What does isolatedDeclarations require and buy?
    Explicit types on exports; in exchange, per-file declaration emit and a public API that cannot be changed by an internal edit.
  4. Why does a dual package need types per condition?
    The ESM and CommonJS shapes genuinely differ, so one declaration file cannot describe both — and half your consumers get the wrong one.
  5. Why run arethetypeswrong?
    Your own tests import from source, so a broken exports map passes everything you run. It resolves the tarball the way each consumer would.
  6. Where must type checking happen if a bundler emits?
    In CI as a required job, and in the editor. Otherwise the only enforcement is whoever has an editor open.
  7. What number tells you whether the checker is in trouble?
    Instantiations, from --extendedDiagnostics. Under ~1M is comfortable; past ~5M something is combinatorial.
  8. What is usually the largest single cost?
    Inferred return types on exported functions — every consumer re-derives them, transitively.
  9. Why does an intersection cost more than an interface?
    The members stay separate and are resolved on each access, rather than being one flat list. It also expands in every error message.
  10. The editor is unusable but CI is fast. What is it?
    One import graph. The language server checks the open file and its dependencies, so an expensive type reached from that file dominates.
  11. When are project references worth it?
    Several packages, and most changes touch one. The cost is building dependencies first and stale declarations producing confusing errors.
  12. Which two settings should you change before measuring anything?
    skipLibCheck and incremental. Two lines, no code changes, often a third off the build.
