The third unit on this line, and the one the other two assume. The Cyber Security unit gives a defender enough networking in a single chapter; this is the discipline itself — how a packet genuinely crosses a network, how addresses and routes are designed, why convergence takes the time it does, and how to find the fault at two in the morning. Physical layer upward, in order. Read it front to back the first time; after that the routing and troubleshooting chapters work as references.

How to use this unit

Each chapter is one page in this folder. Nothing here needs a server — open any file directly and it works, and the whole folder can be copied somewhere else intact. Diagrams come from a CDN; without a connection they fall back to readable text.

Inside a chapter, the left rail lists every chapter and the sections of the one you are reading. [ and ] move between chapters. The interactive panels are wired to the real arithmetic being discussed — propagation and serialisation delay, subnet allocation, queueing, convergence timers, throughput against latency — so changing an input changes the number the way it would on real equipment.

Where this came from

The chapter list follows the roadmap.sh Network Engineer roadmap node for node, then fills in the mechanisms, the arithmetic and the design reasoning the roadmap only names. Where the Cyber Security or DevSecOps units already cover a topic properly, this one links across rather than repeating it.

What is deliberately not here

Vendor-specific configuration syntax, or exam cramming. Commands appear where they illustrate a mechanism, and the emphasis is on why a protocol behaves as it does — which transfers between vendors and outlives any particular platform. Build a lab and type things; chapter 22 covers how.

Adding a chapter

Chapters are declared once in assets/notes.js. Flip ready to true and the rail, this page and the prev/next links all update.
